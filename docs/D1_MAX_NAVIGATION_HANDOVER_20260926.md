**静态跨楼层全局路径已经跑通，定位与原生 SCAN 的数据接口已接通；机器人周边的可靠局部感知、连续定位到运动执行的实机闭环仍未完成。当前最直接的阻塞是近身占据/未知空间导致局部规划起点不合法，不是单纯的 RViz 配色问题。**

## 2. 用户目标与必须保持的约定

- 目标是可靠定位、PCT 全局路线与 SCAN 局部避障衔接，先通过平地单层闭环，再进入跨层执行。算法应模块化、配置化，UI 不绑定 PCT/SCAN 名称作为不可替换流程。
- Web 负责连接和启停；初始位置姿态、三维目标在 RViz 操作，不回到 Web 输入初值。
- 保持 ROS 2 Humble、`rmw_zenoh_cpp`、现有实机 Domain 24，不换 Fast DDS。
- 全局布局看整图、可通行地面、路线和目标；局部布局跟随机器狗，看滚动地图、参考段、障碍与局部轨迹。机器人用固定 RGB 坐标轴表示，不用箭头/状态变色。
- SDK 速度遥测使用 `OnMcData`，回调轻量复制、独立线程处理；不能用低频状态速度或 OnSpeedData 冒充高频里程计。默认定位链也不是直接积分 MC 速度。
- 项目速度上限 1.5 m/s 不是当前验收速度。当前预览参数 0.30 m/s，不授权运动；不得自动发初值、目标、SDK 控制权、姿态或速度命令。
- 不把地图压平、隐藏障碍、改色或重复发布旧时间戳当成算法修复。保留原始地图与证据，不覆盖用户数据。

## 3. 当前工作流及坐标边界

日常从 Web 的“定位与规划”入口启动，用户在 RViz 给初值；真实定位确认后，再给 3D 目标。全局规划从当前定位出发，局部规划取全局参考的一段，并结合实时地图生成局部样条。**全局路径出现，不意味着机器人开始执行。**

定位默认采用 Faster-LIO 局部后验与新 IMU 进行有界高频传播，PCD 匹配提供地图校正，`robot_localization` 承担全局融合；公开位姿与动态 TF 由统一输出层发布。50 Hz 是目标发布频率，要同时看实际间隔、源龄及误差，不能只看计数。

两条容易混淆的地图语义必须保留：

| 数据 | 语义与使用边界 |
| --- | --- |
| 定位地图 / `d1max_loc_map` | 当前定位源 PCD 的坐标。实时机身、传感器及局部地图必须在明确变换后使用这一坐标 |
| 规划处理副本 / `d1max_multifloor_planning` | 地面经过楼层专用修整，不能用一个固定 TF 宣称与定位 PCD 完全等价；线上通过明确的地面映射适配与支持校验衔接 |
| PCT 全局路径 | 当前接口约定是地面支撑参考，不是机身中心的时间轨迹 |
| SCAN 局部轨迹 | 机身参考轨迹；地面到机身高度只能加一次，不能再照搬上游默认偏移 |

公开坐标链包含 `d1max_loc_map`、`d1max_loc_odom`、`d1max_loc_base_link` 与 tracking/lidar 参考点。不得重命名 frame 来代替刚体变换，不得重复发布动态 TF。界面“已定位”不是运动安全标志。

## 4. 问题清单与处理顺序

### P0-1：近身地图阻塞，SCAN 从起点就失败【已复现，当前首要阻塞】

**现象与证据：** 09-26 真实被动录包离线复现中，149 个有效检查周期的机身起点全部阻塞；沿机头约 2 m 的另一查询位置全部通过。末次机身查询累计 free 295、occupied 1、unknown 1060，统计包含查询体积重叠，不是独立体素数量。

**已经做过：** A* 负向取整、额外 XY 体素膨胀、时效通知缺陷已修正；感知由合并点云的单一起点，扩展为前后雷达独立来源、逐点时间和各自射线起点的 `per_sensor_rays` 支路。问题仍存在。

**尚不能确定：** 脚边命中是否确属自体，未知区域分别来自物理遮挡、盲区、投影/同步问题，还是过于保守且未标定的碰撞包络。当前要求整个双圆柱包络具有观测自由空间，比上游默认更保守；该策略与实机可观测性尚未协调好。

**下一步：** 在同一帧/同一坐标中同时输出原始命中、两雷达原点/射线、实测机身/地面、自体几何、occupied/unknown 与查询包络。逐项解释起点为什么受阻，先证实再改过滤或策略。

**验收要求：** 无外物的实际站立场景能产生合法短段；真实障碍在可见绕行空间内触发绕行，通道封堵/遮挡未知则明确拒绝。不能靠清空机器人附近球形区域、减少机器人尺寸或把全部 unknown 当 free 通过。

### P0-2：机器人几何与关节数据不足【未标定 + 遥测失败】

- `body_height_calibrated`、`collision_envelope_validated`、`vertical_envelope_validated`、`sdk_speed_mapping_validated` 均为 false。
- 当前双圆柱只是工程近似，未证明覆盖机身角点、动态腿部、载荷和俯仰姿态；总站立高度不是 base_link 离地高度。
- 用户授权的一次只读 SDK 重连中，关节配置请求无 ACK、`samples=0`；MC/普通状态仍有数据。关节接口还缺源采集时间，不能把接收时间伪装成同步关节状态。
- 后续应核实厂商固件/接口支持，再测量站姿与各传感器参考点。不反复抢控制权，不凭疑似脚部点开启动态自体删除。

验收时应同时说明“实体自体过滤”和“含余量的碰撞包络”各自范围；两者不能混为一个清空区域。

### P0-3：定位连续性与真实输入稳定性未闭环验收【多项缺陷已修，仍需复验】

历史上出现过 IMU 缺口、批量到达、状态/位姿时效耦合、轨迹闪断。已增加有界传播、短缺口容错、同轮次恢复、地图校正与高频输出解耦，并修复积分完成通知延迟。**这些修复不代表所有原因已经消除。**

09-26 静止被动采样支持“没有明显真实位姿大跳变”，但不覆盖快速转弯、楼梯和长时间运行；IMU 源间隔与接收间隔也不同，不能全部归责雷达、网络或回调。

最新预览部署记录在用户尚未重新给初值时为 `waiting_initial_pose`，之后用户关闭了 RViz。因此“新积分立即通知”修复尚未在该新会话重新定位后做连续性复验；此前 301/301 位姿状态有效而桥接撤销路径，是旧通知时序缺陷的证据，不能重复写成新版本仍在复现。

后续应对真实录包统计：原始 IMU/点云源间隔、接收间隔、实际输出最大间隔、校正数据龄、epoch/seed 变化及规划撤销原因。先复现断链在哪一层，再收敛参数，不统一扩大所有超时阈值。

验收必须同时包括静止不漂、移动连续、真实断流停止授权、恢复不复活旧轨迹。低频 PCD 校正不能阻塞高频运动输出；画面持续存在也不能代替新鲜位姿。

### P0-4：运动闭环尚未放行【明确的实现边界】

当前入口为 `LIVE_VISUALIZATION_NO_MOTION`；`prepare_motion` 明确拒绝当前 `per_sensor_rays` 后端切换运动。已有跟踪器、近场碰撞停止、SDK 门控与状态机代码，但不是当前正在执行的链路。

SDK `Move` 输入是归一化比例而非 m/s，文档低速映射存在矛盾，不能把规划速度直接塞给 SDK。独立运动入口原本只针对低速平地；跨层路线显示不等于允许上楼。

先解决 P0-1～3，再在明确授权和现场安全条件下进行低速平地验证，包括起停、真实绕障、控制权丢失、断流、取消、更换目标及停车距离。之后才讨论楼梯模式切换、上下楼支撑与落足安全。

### P1-1：SCAN“接入”和“完整官方能力”仍有差距【已核对】

- 真正调用了原生滚动 GridMap、投影 A*、rebound/B 样条优化；不是用直线或自写路径冒充 SCAN。
- 当前配置还加入 PCT 参考引导、时效/任务代次和最终支持检查，并非零修改的官方默认方案。尤其参考权重 20 是本地参数，不是官方建议值。
- 投影 A* 主要搜索 XY 并使用高度参考，不是可任意飞行的三维搜索，也不自动生成足端落点或识别全部悬崖。
- 论文 V-C 描述的虚拟边界层脱困，在核对的公开 main/ROS2 分支及本地代码中未找到。沿原参考线缩短/延后目标，不等同于论文脱困。

若以后补脱困，应作为独立模块和新能力验证；不能把地图外虚拟层当作可执行自由空间，也不能用它掩盖起点感知错误。

### P1-2：RViz 已分层，但没有完整显示官方 a2 诊断信息【显示差距】

当前局部布局显示灰色原始占据体素和真实滑动边界，膨胀层默认关闭；轨迹经结果配对校验后画为绿色线，未展示原生速度色/球点与双圆柱包络。占据显示还有雷达参考高度以上 0.35 m 的裁剪；内部窗口仍为 12 × 12 × 6.4 m、8 cm 分辨率，不能将显示薄层误认为内部没有完整地图。

应在局部布局补足可独立开关的占据/膨胀、碰撞包络、参考段、搜索尝试与有效轨迹，明确颜色含义。官方彩虹不能直接解释成 ESDF 或通行代价；更不能只换色便宣称功能一致。

保留现有双布局和机身坐标轴，不重新叠满整幅楼层地图。失败尝试可以显示，但不能当作已通过的执行轨迹。

### P1-3：前端下沉与标定根因尚未闭合【历史问题，不能视作已解决】

长走廊逐渐下沉、回环后整体被拉回，是必须单独追踪的建图质量问题。回环闭合成功不能证明前端外参、IMU 时间与噪声模型正确，换中心 IMU也未自动解决。

已有审计不支持“重力只在开头估计、之后永久锁死”这一简单解释；零偏和重力可以随滤波更新。中心 IMU 的持续下沉也不能只归因于持续丢帧，仍需核对几何外参、逐点时序、实际消费与运动激励。

下一轮保留同一 bag 和二进制/参数基线，做单变量前端实验，不依赖回环、不以强制水平地面或动态改重力掩盖误差。旧静态地图处理仅是该地图的规划准备，不是通用 LIO 修复。

### P1-4：NUC 资源预算与整机实时性未验收【已优化，但仍有差距】

09-25 同机真实地图离线基准已比旧版改善，不能继续把旧 7.42 GiB 峰值当作当前成绩：

| 指标 | 已记录的新结果 | 边界 |
| --- | --- | --- |
| 83 m 跨层首次（含加载）/重复 | 3.60 s / 0.93 s | i9-14900HX，指定地图与端点，不含全套 ROS/渲染 |
| 7 m 同层、地图已加载 | 约 46 ms | 不是任意路线几毫秒 |
| 受预算约束的全局 worker | 常驻约 2.75 GiB，初始化峰值约 3.58 GiB | 单 worker，非整机峰值 |
| 逐束投影 / 非空积分加两处查询 P95 | 约 9.95 ms / 45.52 ms | 09-26 本机录包离线值，不是 NUC 最坏界 |

全局 worker 已限制为最多两个逻辑 CPU、OpenMP 2、BLAS 1、nice 5；这不是独占资源或内存硬配额。后续在 NUC 同时运行定位、感知、规划、RViz，测冷/热启动、不可达搜索、目标替换、RSS/CPU 与延迟分位数。`-march=native` 产物迁移时要重新构建，不能照搬本机动态库。

## 5. 下一位接手者的执行顺序

1. **冻结并记录基线。** 采用提交 `832a520` 对照当前运行目录；保存会话参数、地图哈希和实际加载程序版本，不先批量调参。
2. **先解释近身阻塞。** 复用真实录包，增加逐体素来源与包络诊断，核对自体、地面、unknown 和双雷达射线。同步完成 a2 所需诊断显示，但显示与算法改动分开验证。
3. **检查定位到局部地图的完整时序。** 使用原始数据时间验证投影、地图积分通知、位姿与路径有效期，记录真正触发撤销的原因。
4. **完成离线回归。** 真 bag 加独立解析障碍场景分别测试空场、合法绕行、低障碍、遮挡未知、封堵、断流恢复与目标取消；不能只用静态 PCD 裁剪证明动态避障。
5. **经授权再验收低速平地闭环。** 先被动观察，再检查跟踪/SDK 标定与停止链路；不得通过改 false 验收标志跳过实测。
6. **最后做跨层执行与 NUC 整机验证。** 跨层要另验楼梯模式、姿态变化、支撑、顶空、楼层关联与恢复，不把平地通过直接外推到楼梯。

每项完成都应留下输入、参数、程序版本、预期、结果和失败样例。失败阶段应区分输入、起点碰撞、搜索、优化、最终碰撞、支持检查、时效和执行，不再统一报“优化失败”。
