# 当前待办与验收边界

截至 2026-09-12 源码整理。此次是保存当前工程基线，不是再次宣称定位问题全部解决。

## 已确认、尚未修复

1. **短时失锁导致轨迹被清空。** `navigation_output.py:on_map` 用 `NavigationState.key()` 的变化判断清轨迹；该 key 在地图契约无效时返回 `None`。同一 epoch / seed 的有效→无效→有效也会触发空 Path，并不一定真的换了坐标系。之前已用不创建 ROS 端点的回调测试重现；本次不修改此算法。后续应区分短时失效与坐标轮次变化，定义保留历史、断段和新轮次归档策略并补回归。
2. **高频传播的协方差仍是简化模型。** 从 LIO 后验使用后续 IMU 传播在结构上合理，但当前协方差不是原生完整误差状态协方差的严格传播，不应称为最优或已统计标定。
3. **全局融合存在同源相关性。** LIO / IMU 派生 twist 和 PCD 匹配 pose 共享部分激光信息；保守协方差下限并没有建立完整跨源相关模型。后续需评估重复信息、延迟校正和滤波一致性。

## 仍需实机验收

- SDK ↔ 机身 ↔ 雷达/IMU 的物理外参、轴向、杆臂与时间对齐。目前 `extrinsics_verified=false`、`time_alignment_verified=false`、`navigation_ready=false`。
- 静止漂移、加减速/转弯、振动、遮挡、走廊退化、快速运动和长时间断续运行。已有合成测试不是实机厘米级精度或高速上限证明。
- 实机出现过 IMU 时间间隔超限及有界重初始化。恢复机制不等于上游缺帧原因已消除；现有记录不足以单独归责发布端或网络。
- APP 退出后的 SDK 接管已有状态机及离线回归；APP 往返切换、超时/迟到回执和长期 MC 稳定性仍需现场验证。一次接收约 50 Hz 不能保证所有会话一直正常。
- 地图本身的地面倾角、重复结构、处理后几何保真和栅格可通行性；不能靠压平点云或补造障碍来冒充标定/通行性验证。

## 工程整理后仍保留的限制

- 此仓库是源码快照，不是跨机器一键部署包。旧脚本仍有本机绝对路径，部分浏览器验收脚本使用本机 Go2 的 Playwright；需配置环境后运行。
- Foxglove JSON 是之前的导出文件，云端/桌面布局修改不会自动写回 Git。本次没有更新在线布局。
- UI 构建中的 Three.js 点云分块仍有大于 500 kB 的提示；未在整理任务中改资源加载策略。
- 模块内 `VERIFICATION.md` 和交接文件按日期保留历史；其中“已停止”“未提交”等是当时事件，不是当前服务或 Git 实时状态。
- 第三方源码、历史规划/控制实现保留来源和许可证，不等于已接入正式链路。Nav2 实机执行、跨层地图切换、楼梯导航尚未完成。

后续定位修改应先针对上述边界设计回归，再在用户授权的实机连接条件下验收；不要把 Git push 成功作为机器人功能验收。
