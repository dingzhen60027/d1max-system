# 中心 IMU 链路下沉：离线排查结论与标定决策

日期：2026-09-20。对象：`slam_raw_20260917_171716_fe8f38`，以及已保存的中心 IMU Faster-LIO **原始前端**状态。不是 SC-PGO 优化结果。本轮不回放、不启动 ROS、不连接机器狗，不改默认配置、可执行程序或 Zenoh。

## 结论先行

**尚未找到足以独立确认的唯一根因，也没有完成修复。现在应停止按“哪组参数让地图更平”盲选外参，转入直接 LiDAR—中心 IMU 标定准备。**

本轮不是简单重复上一轮：新增了独立的 LiDAR-only 旋转观测、中央专用连续性统计，以及两颗 IMU 在同一组点云/时间支持上的对照。结果不支持把问题单独归给前 IMU 丢数据，也没有证据指向中心 IMU 硬件损坏。新拟合的旋转/时移不稳定，**未批准、未写入生产配置**。

“暂未通过这次有限抽样验证”不等于“整个旧 bag 没有标定价值”。旧包保留为回归集；专用运动数据能帮助分离当前互相混杂的时间、外参、传感器偏置与点云配准误差。

## 1. 中心 IMU 没有缺口时，为什么仍下沉

这次只统计 `/imu_driver/imu_central`，没有拿前雷达 IMU 的缺口替代它。

| 事实 | 短段前端，177.8 s | 旧完整原始前端，982.7 s |
| --- | ---: | ---: |
| 中心源最大时间间隔 | 59.990 ms | 74.981 ms |
| 无 >15 ms 源缺口的状态区间比例 | 93.1% | 93.5% |
| 上述无缺口区间的净估计 ΔZ 累加 | −0.7101 m | −4.0253 m |
| 全部区间中心原点估计 ΔZ | −0.7731 m | −4.3927 m |

在同一估计速度层内，下降也不是只发生在缺口区间。故降低“中央长期连续断流是主要解释”的优先级，但不排除间歇缺口造成早期误差后继续传播。

这些是记录的源时间和前端估计，不是独立高度真值，也不是算法逐次实际消费 IMU 的 trace。旧完整运行没有扫描 header 表，仅分析相邻状态区间。中央六轴重复值及驱动滤波相位仍须核查。

详见 [中心链连续性报告](central_timing/central_timing_audit.md)及其同名 JSON。

## 2. 不用 LIO 结果反过来证明外参

从旧包选择 4 个相离运动窗口，读取原始 `/front_lidar`。相邻扫描配准完全使用单位矩阵初值，**不使用 LIO 位姿、不使用 IMU 初值、不做 IMU 去畸变**。

- 36 对扫描；正反配准、不同体素和几何门槛后，27 对保留，失败项也保留。
- 原始点坐标是 `rslidar_head`，没有隐式套用旧点云归一化旋转。
- 对所有候选时移使用相同样本支持，中央最大允许源间隔 20 ms 时剩 19 对，分属 4 个窗口。
- 模型方向为 `p_prev = R_prev_from_next p_next + t`，与正向机体相对旋转一致；不应再取逆或负号。
- 时移搜索 −80…+80 ms、步长 2 ms。正 lag 表示中央 `t+lag` 对应 LiDAR 有效时刻 `t`，若补偿 header 则减 lag。

扫描横跨约 100 ms，不是刚性瞬时快照；扫描中点只是近似有效时刻。这是**独立一致性诊断**，不是高精度标定仪。

### 新候选为什么没有采用

采用相同向量 Huber 损失（δ=0.02 rad/s）优化固定/自由旋转，最终以 [lidar_central_fit_v2.json](lidar_central_fit_v2.json) 为准：

| 19 对共同支持，主配准 | 结果 |
| --- | ---: |
| 自由旋转与历史旋转的角度差 | 3.397° |
| 自由旋转最佳 lag | +6 ms |
| 固定历史旋转最佳 lag | +8 ms |
| 自由 / 固定历史旋转的向量 RMSE | 0.04459 / 0.04443 rad/s |
| 稳健目标改善 | 约 1.6% |
| 留出最后一个完整窗口后，拟合旋转相对全样本变化 | **12.58°** |

因此，“新矩阵比旧矩阵差几度”不能解释成“旧外参错了几度”。训练目标几乎不变，参数却对窗口选择敏感；不同体素与反向配准拟合也有变化。不能从这里挑一组数覆盖当前外参或 −13 ms 时间补偿。

按 SO(3) 逐样本积分复核，均值角速度近似与旋转累计的差异最大约 0.00365°，远小于本次 LiDAR/IMU 残差，未发现取逆、符号或该小角度近似能解释主要差异的证据。

早期 `lidar_central_fit.json` 是方法草稿，固定/自由模型的稳健偏置目标未完全统一，保留仅用于审计。最终数值使用 v2，勿混用。

详见 [独立点云配准方法](lidar_motion/lidar_rotations.md)。

## 3. 同一观测下，中心 IMU 是否明显比前 IMU 差

额外对照取**两颗 IMU、全部候选 lag 都有支持的共同扫描**。没有把不同数量、不同运动片段的残差直接相除。

20 ms 源间隔门槛下共 16 对、4 个窗口，设备旋转候选与主配准的结果：

- 前雷达 IMU：0.04462 rad/s。
- 中心 IMU：0.04503 rad/s。
- 中心/前的比值约 1.009；不同 ICP 变体及 20/35 ms 门槛下，该比值约 0.949–1.011。

**没有观察到中心 IMU 在此诊断中明显更差。** 这既不证明两颗都已标好，也不证明 LiDAR 畸变就是根因；它说明当前有限的原始扫描配准误差，尚不能分离传感器问题和配准/有效时刻问题。

时移最优值也随共同支持和配准变体变化。不能把其中某个值当作物理采样时间标定。

详见 [同条件前 IMU 对照](front_control/front_control.md)和 [最终证据](front_control/front_control_v2.json)。

## 4. 哪些环节还没有被真正标定

1. **雷达—中央旋转与直接时间关系。** 现有 `R_C_F` 主要由两颗 IMU 的角速度拟合；还需要正确的雷达点轴到前 IMU 轴关系才能组成 `R_C_L`。两 IMU 相互吻合，不等于整条 LiDAR→中央链已认证。
2. **中央 IMU 的测量原点/杆臂。** 当前约 0.366 m 的杆臂来自名义安装位置假设，尚无独立测量认证。前雷达内部毫米级 IMU 外参不能代替它。
3. **中心原始驱动语义。** 实际硬件对应、轴图、加速度/角速度单位、采样与发布时刻、重复六轴与内部滤波尚需从真实驱动核对。消息频率不是硬件新测量频率。
4. **加速度偏置与比例。** 现有低动态窗口的姿态覆盖窄，不能分离完整加速度内参与重力。不能直接把行走中的滑窗加速度均值当成重力。
5. **前端估计与配准。** 仍保留几何退化、去畸变及滤波噪声/可观性等问题；不能因存在未标定量就宣布 Faster-LIO 一定无问题。

上一轮整圈原始地图即使拟合一个最佳平面，局部地面中心残差 RMSE 仍约 0.74 m；因此不是只给最终 PCD 转一个固定角度就能修复。该证据见 [地面形变报告](../timing_bias_geometry_20260920/floor_shape_audit.md)。本轮不做压平、锁高或回环拉回。

## 5. 下一步：专用标定，而不是继续盲换参数

需要下一次实机可用时完成以下采集。**当前没有机器狗连接，本轮没有执行动作或补录。**

- 核对上述硬件、轴、单位和时间定义，保存驱动/固件/坐标转换配置；量测或核实中央测量原点。
- 在安全且静态结构丰富的区域录 A 段：起止各确认静止 20–30 s，中间由用户操控低速左右转向、温和加减速和停顿；仅在厂家允许且安全的姿态模式中补充小幅俯仰/横滚。禁止为了激励搬翻整机或强行走危险坡梯。
- 另录 B 段不同运动序列作留出验证，不拿 B 段反复调参。原始点时间、中央 IMU、前内置 IMU 对照和配置快照必须保留；不提前改原始录包时间戳。
- 单前 LiDAR＋中央 IMU 先标定和验证；后雷达独立加入，防止多个外参互相掩盖。
- 候选通过独立窗口稳定性、直接传感器残差和无回环前端复核后，才考虑更新默认配置。地图看起来平不能作为唯一验收。

[完整标定就绪性与采集方案](calibration_readiness.md)已准备。LI-Init 是适合评估的直接 LiDAR–IMU 标定候选，但官方版本为 ROS1/catkin，AIRY96 点格式和 ROS2 离线入口仍需适配；**不是本机已经安装并跑通的能力**。[官方说明](https://github.com/hku-mars/LiDAR_IMU_Init)
