# 通用 Faster-LIO 前端可靠性检查与输入防护

日期：2026-09-19。状态：**离线检查和输入防护验证已完成；前端下沉尚未解决，不能宣称已达到可靠建图验收。**

最新进展：已完成[单前雷达＋中心/内置 IMU 三组最小链路对照](minimal_front_lio_20260919/README.md)。内置 IMU＋设备外参仍有约 −0.668 m 的短段估计高度变化；不能将问题唯一归到中心 IMU 或双雷达拼接。见第 9 节。

本轮不采用水平地面约束、地图压平、Z 锁定、回环修正或运动中加速度滑窗重置重力。没有连接机器狗、调用 SDK、发送运动指令或更改时钟。所有 ROS 验证继续使用 `rmw_zenoh_cpp` 和原有本机 Zenoh 配置。

## 1. 最重要的新结论

关闭后雷达不能消除早期下沉。对同一原始包、同一批 1,660 组已配对扫描做前端对照，单前雷达仍有约 0.80 m 的估计高度下降，与双雷达约 0.82 m 接近。因此，不能把后雷达拼接解释为本段下沉的唯一来源，也不应把 front-only 模式直接发布成“已修复版”。

原始静止数据还有约 0.8° 的单前雷达地面—IMU 重力不一致。它发生在建图之前，支持继续检查公共的雷达—IMU几何与数据链，但不能区分所有外参、加速度偏置、量测系统误差和初始残余运动，更不能直接把 0.8° 写入补偿参数。

已实现的点云入口防护与 IMU 连续性检查解决的是明确的数据处理风险，不是已经证明的下沉根因。

### 排除的无效试验

首次工具吞吐检查 `maps/runs/20260919_frontend_ab_dual_180s` 在约 94 秒时被主动中止，**不参与对照**。原因是新增 Python selector 给 ROS 的 `data` 属性赋 bytes，触发逐字节 Python 校验，导致跟不上点云。已改为 `array('B', ...)` 的类型化缓冲，之后两组均收到完整、相同的 1,660 组扫描。

该首次中止还暴露旧 supervisor 的 rclpy 信号处理抢占取消回调、令 partial save 失败的问题；已让 supervisor 保留自己的信号处理，selector 仅忽略同一 ROS context 已关闭的已知清理竞态。正式双雷达组的 selector 退出时仍遇到旧版清理竞态（returncode=1），但这是完整 CSV、前端轨迹及地图均保存后的退出问题；正式前雷达组包含清理修复并全部正常退出。没有删改原始运行证据。

## 3. 标定核查：有不一致，没有可批准的替代外参

完整可复现脚本、测量来源、ROI、公式与限制见 [geometry/README.md](geometry/README.md)。

- 三组开头低运动扫描，前后 header 相差仅约 0.012～0.020 ms。
- 按多个显式 ROI 检查，前后地面法向差约 1.126～1.266°。之前约 1.5° 与点集选取不同；两者都不是可直接使用的标定角度。
- 中心 IMU 当前外参下，前地面与重力夹角约 0.777～0.861°。使用每帧独立 300 ms IMU 均值复核，结果相近。
- 初始静止帧前后视野没有足够直接重叠，不能把单帧 ICP 的无对应结果当作完美标定。
- 条件性解释本机合法前雷达 DIFOP 后，前方一致性有所改善，但后方没有同步改善；录包时实际驱动是否还有额外坐标变换未核实。
- 中心 IMU 杆臂仍是名义值，不能由两颗 IMU 的陀螺旋转拟合证明。

本轮没有生成可加载的替代标定 YAML，也没有改默认外参。完整旧 bag 未来可能支持跨时刻联合标定，本次有限静止帧检查并不能证明它绝对不可标定；但没有充分验证前，不将猜测矩阵部署到默认链路。

## 4. 已实现的模块化可靠性修复

### 点云入口

实现于 `src/faster_lio/src/pointcloud_preprocess.cc`，测试于 `test/test_pointcloud_preprocess.cpp`：

- 空云、空指针、未知类型和非法配置不再访问越界或返回上一帧残留。
- 过滤非有限坐标/强度、非法 ring、非法/溢出时间。
- 错误尾部时间不再决定整帧的时间处理；有效乱序时间排序后确定扫描末端。
- 明确存在但 datatype/count/offset 错误的 `time` 字段拒绝处理。
- 保留缺失 `time` 或全零时间的历史 legacy 回退，不能把该回退宣称为真实逐点时间认证；当前 AIRY adapter 有合法的 FLOAT32 逐点时间。
- 正常 1,000 点数据在三种 stride 下，与原 timestamped 路径逐字段一致。

空云不再重发旧点云，但原同步器仍可能进行内部纯 IMU 预测后停止本帧输出；本轮未将其包装成“所有激光异常都已获得质量判定”。

### IMU 连续性

纯 C++ 模块：`src/faster_lio/include/imu_continuity.hpp`。与建图同步器集成，但不复用定位模式的自动恢复逻辑。

```yaml
laserMapping:
  ros__parameters:
    mapping:
      imu_continuity:
        mode: fail_closed
        warning_gap_sec: 0.015
        maximum_gap_sec: 0.030
    diagnostics:
      input_log_path: /absolute/path/to/a/new/input_audit.csv
```

以上阈值是显式检查参数，不是已针对 D1 Max 运动速度认证的安全界限。当前旧 bag 的短段已有 85 个 >30 ms 间隔，直接启用这份严格配置会中止，不能以提高阈值或虚构插值掩盖数据缺口。

- `disabled`：默认兼容模式；不会默默改变旧生产行为。
- `observe`：记录真实缺口和时间问题，但允许继续；不代表结果有效或已安全恢复。
- `fail_closed`：在实际积分前检查覆盖、缺口、非有限数据和时间倒退；故障锁存后停止新增地图、里程计、点云与 TF，停止缓存增长，需要新运行显式重新初始化。

检查包含上一传播终点、初始化到首帧转换、跨缺失雷达帧的 IMU 区间及真实左右支撑样本。重复数值与重复时间戳分别处理，不合成样本。

`/mapping_input_status` 为 reliable / transient-local JSON 状态，含 `scope=mapping_input_continuity`、`guard_enforced`、`mapping_halted`、`requires_new_run`、`input_fresh`。这是**输入连续性状态**，不是总体定位精度或可导航认证。Web 目前未接该新状态，不应仅凭进程存活宣称已正常。

## 9. 单前雷达与内置 IMU 最小链路对照

用户继续授权排查后，完成新的三组 180 秒 Zenoh 无回环试验。统一到物理前雷达原点：中心 IMU＋单前点云 ΔZ −0.7748 m；前内置 IMU＋本机设备外参候选 −0.6678 m；前内置 IMU＋历史旋转、相同设备杆臂 −0.8034 m。每组同 1,660 组输入扫描、1,641 个有效状态及约 177.8 秒轨迹。结果说明中心链和后雷达点不是本段下沉的必要条件，设备候选虽影响数值但没有修复问题。

重力参考审计发现估计 g 在初始化之后和末段姿态变化时仍在调整。以固定最后一帧 g 重算高度可以改变报告数值，但末 10 秒平均 g 得到的数值又不同；这不是地图已正确、更不是可批准的调平修复。输入中存在的 IMU 缺口和中心重复值也仍需区分来源，不能据此定性硬件故障。

全部结果、候选来源、严格对照、输入记录和退出证据见[本轮汇总](minimal_front_lio_20260919/README.md)。每组仅保存一份实际 PCD；三组自有进程已退出，默认安装库及生产参数不变，未连接机器狗、未调用 SDK、未改变通信中间件。
