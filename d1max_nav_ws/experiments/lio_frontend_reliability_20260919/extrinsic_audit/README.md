# 外参专项排查：程序方向正确，不等于物理标定正确

日期：2026-09-19。对象：`slam_raw_20260917_171716_fe8f38` 和中心 IMU 建图运行 `20260919_125722_855277_central_imu_faster_lio_sc_pgo_zenoh` 的保存配置。

本次只做离线读取、公式复算和少量原始消息检查。没有连接机器狗、启动 ROS/回放、修改生产参数、改通信中间件或覆盖已有地图。文中的历史短段 A/B 结果来自上一轮，不是本轮新运行。

## 结论先行

**当前外参链有具体、可复现的标定疑点，不能称为已经验证可靠的外参；但还没有证据把全部下沉唯一归因于某一个外参角度。**

最值得优先核实的是“前雷达点云 → 前雷达内置 IMU”这段历史旋转。更换中心 IMU 后，这一段仍被沿用：新拟合主要对齐了两颗 IMU 的角速度，没有独立完成雷达与中心 IMU 的全套时空标定。

程序里的矩阵方向、行列顺序、四元数顺序和逐级组合没有发现错误。这里的问题不是“完全没填外参”，而是**当前填入的外参混合了历史旋转、两 IMU 的拟合结果和名义安装位置，物理精度尚未独立验收**。

## 1. 当前外参到底怎样来的

为便于理解，用等效物理链表示当前旋转关系：

```text
原始前雷达点云
  → 历史雷达—内置 IMU 旋转（仍在沿用）
  → 前内置 IMU—中心 IMU 的角速度拟合旋转
  → 中心 IMU 坐标
```

程序实际通过中间归一化点云坐标 N 实现，数学等价。采用 `p_target = R_target_source p_source + t_target_source`，有：

```text
R_C_N = R_C_F · Aᵀ
当前隐含 R_F_L = Aᵀ · R_N_L
当前实际 R_C_L = R_C_N · R_N_L
```

其中 L 是原始前雷达点坐标，F 是前内置 IMU 原始轴，C 是中心 IMU 原始轴，A 是旧 IMU 适配器的 `Rx(+90°)`。完整复算、输入 SHA256 和代码行见 [代数链审计](chain/README.md)。主检查已独立重跑，JSON 与原审计结果完全一致。

## 3. 这次新排除了什么

### 软件组合方向

- 当前 `R_C_N` 与 `R_C_F Aᵀ` 精确一致；四元数 xyzw 往返误差为浮点量级。
- 后雷达逐级变换与完整复合变换一致。
- 中心 IMU adapter 只做单位换算和时移，不额外旋转矢量。
- 点云 adapter 做原始坐标到 N；LIO 再做 N 到 C。没有发现同一旋转重复应用。
- 发布同参数静态 TF 不等于点云被重复变换，必须看实际数据处理路径。

### 原始点云有没有被驱动预先倾斜旋转

抽取前、后各两帧，共四条原始 `PointCloud2`，直接用设备 DIFOP 中每条扫描线的标定角和 AIRY 镜心模型检验，不使用地面、墙面或已有轨迹作为真值。

原生模型的角残差 RMS 只有 **1.25～1.30 × 10⁻⁶°**，与 float32 坐标舍入相当。这强烈支持：**抽查点云没有额外 roll/pitch 旋转或平移，不是已经转换到内置 IMU 坐标后又被误转一次的点云。** 这些微小残差仅说明坐标生成公式一致，不是实际传感器或外参精度。

但扫描线锥面无法判断绕原生雷达 Z 轴的额外 yaw，也不能证明内置 IMU 消息没有独立转轴。四条消息不是整包逐帧认证。详见 [原始扫描线几何核验](beam/README.md)。

另用相同四帧交换前后两设备的扫描角标定做交叉检查：正确候选约为上述舍入量级，交换后约 **0.322～0.324° RMS**。这支持 `/front_lidar` 对应 SN `3009bede1530`、`/rear_lidar` 对应 SN `300dbeda0056` 的扫描角指纹关系，但不是对实际 driver 配置的直接读取证明。指标见 [设备指纹交叉核验](beam/cross_device_report.json)。

官方当前 [AIRY 解码器](https://github.com/RoboSense-LiDAR/rs_driver/blob/main/src/rs_driver/driver/decoder/decoder_RSAIRY.hpp) 分别处理设备 q/t、IMU 量程换算和可选点云安装角变换；读到设备 q/t 本身不等于驱动已把点云应用了该变换。该源码是模型依据，不是对录包时驱动二进制版本的鉴定。

## 4. 为什么还不能说“改这 0.58° 就好了”

1. **来源差异不是误差真值。** 设备 q 的方向定义、IMU 消息轴处理、剩余点云 yaw 约定仍需一致核验。
2. **初始参考倾斜与沿途估计漂移不是同一件事。** 一次固定的整图旋转只会改变整图朝向；错误的雷达—IMU关系进入去畸变和融合后可能引入持续冲突，影响姿态、偏置和高度估计。当前数据尚未证明具体哪条机制贡献最大。
3. **单前雷达也下沉。** 上一轮相同扫描短段对照中，约 40 m 路程的估计高度变化：双雷达 −0.823 m，单前雷达 −0.803 m。不能只修后雷达拼接就宣称解决问题；这些不是有独立轨迹真值的精度认证。
4. **加速度偏置与姿态在有限低运动数据中不易分开。** 一条地面法向不足以确定完整三维旋转和位置，更不能同时唯一估计时间偏移、偏置和杆臂。

因此不做“按地面硬补 0.8°”、滑窗加速度直接重置重力、锁 Z 或靠回环拉平的修复。

## 5. 仍缺的证据与修复顺序

录包的 [快照索引](../../../bags/slam_raw_20260917_171716_fe8f38/snapshots/index.json) 标记为 `local-files-only`，没有完整保存录包时实际雷达驱动配置和构建版本。当天设备 DIFOP 在 15:29 左右读取，之后被复制进 17:17 的录包快照；不等于录制期间重新抓取。

- DIFOP 的设备安装 roll/pitch/yaw 为零；不能单凭这一项排除 driver 自身配置变换。
- topic 与点云/IMU 的同名 `frame_id` 不是两种数据物理轴相同的证据。
- 厂商 localization 的 `lidar_to_base_output_transform_enabled` 是定位输出设置，不是雷达驱动的 `ENABLE_TRANSFORM`。
- 旧 OTA 雷达—IMU旋转矩阵存在非正交记录，不能直接复制替换或无说明地“正交化成标定真值”。

后续应先统一原始轴约定和标定来源，再在隔离试验里验证完整空间/时间链。现有 bag 可以继续尝试跨时刻、多方向运动的标定和留出段验证；不是必须等连机才有任何进展。若现有运动/几何约束不足，再补录专用数据和实测安装位置。

条件性设备旋转必须经过完整组合：

```text
R_C_N_candidate = R_C_F_gyrofit · R_F_L_DIFOP · R_N_L_currentᵀ
```

**它仅作为诊断矩阵保存，不是批准部署的外参，也不能将设备原始 q 直接填入 N→C。** 先验证单前雷达，不依赖回环和水平地面约束；通过后再加入后雷达，分别检查收益与风险。

本轮产物仅包括本报告、离线脚本和诊断 JSON。没有生成可直接加载的替代标定 YAML，没有修改默认建图链路。
