## 发现

### 1. 地面方向差异可复现，但不是完整外参标定

在归一化前雷达坐标系中，三种地面 ROI 分别为：

| ROI | 前方 y / m | 后方 y / m | 共同 x 范围 / m | 三帧法向夹角 / deg |
| --- | --- | --- | --- | --- |
| 近处 | 0.7～2.5 | −2.8～−1.1 | ±1.0 | 1.248 / 1.241 / 1.245 |
| 较大 | 0.5～5.0 | −3.2～−1.0 | ±1.4 | 1.144 / 1.137 / 1.126 |
| 中央窄带 | 0.7～2.5 | −2.8～−1.1 | ±0.6 | 1.263 / 1.266 / 1.242 |

地面候选 z 范围为 −0.65～−0.30 m，使用五轮 SVD 拟合并剔除距平面超过 1.5 cm 的点。各自拟合 RMSE 为约 3.9～5.7 mm。

如果这些前后区域确实属于同一个物理平面，当前外参下的两路地面方向不一致。差异稳定，并非明显的接受配对时间错误。但是两路看到的是不同的实际地面区域；地面结构、雷达内部角度标定和量测系统误差也可能影响结果。**不能仅由这一项断言某个安装角错了 1.25°，更不能直接据此修改外参。** 前一轮约 1.5° 的结果同样是与选取点集有关的线索，不应解释成完整标定值。

### 2. 静止扫描没有足够的直接重叠来做可靠 ICP 标定

在 7 cm 下采样后的点云中，后雷达到前雷达的最小最近邻距离分别为 0.856、0.834、0.835 m；20 cm 和 50 cm 范围内对应点均为 0。初始姿态、当前外参和这个空间范围下，前后视野互不重叠。

诊断 ICP 的 `fitness=0`，其 `inlier_rmse=0` 是**无对应点**而非完美匹配；返回单位矩阵也不是“当前外参已正确”的证据，不能作为候选输出。

### 3. 多方向墙面不足以形成可验证的跨传感器关联

辅助平面提取能在前方找到纵向墙面、在后方找到另一方向墙面，但主要墙面的位置不同，不是同一物理墙。地面和主天花板可能属于相同的延伸平面，但彼此大致平行，仅靠它们不能确定全部 6 自由度。不能假定所有墙正交，不能把两个不同位置的墙强行匹配。

## 工程结论

1. 保留“双雷达地面几何一致性待验证”的风险标记。当前数据提供了约 1.1～1.3° 稳定差异的诊断证据，尚未提供可批准的完整旋转 / 平移修正。
2. 本次有限静止帧不足以完成 6DoF 标定，**本目录不输出可供生产加载的标定 YAML**。也不把地面法向强制对齐写入建图配置。
3. 尚不能断言完整 bag 一定无法标定：后续运动可能让两个雷达先后观察相同结构，但这需要跨时刻关联、轨迹 / 运动约束和独立验证，不能用已经漂移的 LIO 轨迹当真值闭环自证。
4. 若要可复用的工程标定，建议专门采集：可关联的多个不同方向平面、多个静止姿态和充分的多轴运动；保留两路原始点云与 IMU，留出独立验证段，辅以安装位置测量。前后不共视时需采用支持非共视 / 跨时刻约束的方案，而非直接单帧 ICP。
5. 当前最小可控的前端验证仍是同一批有效扫描上的单前雷达 / 双雷达对照。先判断双雷达融合是否使下沉显著恶化，再决定标定与模型修复优先级。此实验不需要水平地面约束进入估计器。

以上结论不依赖回环，也没有对地图进行拉平或 Z 轴锁定。

## 补充：静止重力与单雷达地面是否一致

使用缓存的原始中心 IMU / 前雷达内置 IMU 前 2 秒均值，仅把用户确认的水平地面作为离线检查依据。脚本 `validate_gravity_geometry.py` 不读完整 bag、不初始化 ROS，结果保存在 `gravity_geometry_report.json`。

中心 IMU 原始均值约为 `[-0.00251881, 0.00907307, -0.99967765]`（原始 g 单位）；单位化并通过当前 `R_C_N.T` 转到点云坐标 N，得到预测地面向上法向：

```text
[0.00357168, -0.01633474, 0.99986020]
```

在三对扫描、三种 ROI 中的夹角范围如下：

| 验证链 | 前雷达地面 / deg | 后雷达地面 / deg |
| --- | --- | --- |
| 中心 IMU + 当前 `R_C_N` | 0.777～0.861 | 0.981～1.162 |
| 前内置 IMU + 历史点云归一化 / 单位外参 | 0.740～0.826 | 0.998～1.178 |
| 前内置 IMU + 条件性 DIFOP 链 | 0.286～0.395 | 1.245～1.401 |
| 中心 IMU + 条件性 DIFOP 链 | 0.298～0.407 | 1.211～1.369 |

这里的“条件性”严格表示：将当前机器前雷达 SN `3009bede1530` 的 DIFOP q/t 解释为 `p_F=R_F_L p_L+t_F_L`，同时假设 bag 的原始点云 / IMU 尚未施加额外未记录变换。它不是使用地面点反拟合旋转。

**单前雷达在当前配置下也存在约 0.8° 的静态重力—地面不一致。** 只关闭后雷达并不能被预先视为充分修复。由于这是尚未建图的原始静止扫描，这一差异不能由后端回环或长时间累计漂移解释；但还混有 IMU 加速度偏置、实际静止程度、传感器量测系统误差和地面真实平整度，不能只用它反推出一个唯一外参错误。

JSON 同时记录每帧时间附近 300 ms 的中心 IMU 独立局部均值对照，避免只报告全局初始均值的结果。静态法向一致性不能验证航向或杆臂。

### DIFOP 候选的组合公式与禁止误用

定义 L 为原始前点云坐标，F 为原始前内置 IMU 轴，N 为当前归一化点云轴，C 为原始中心 IMU 轴。则：

```text
R_C_N_candidate = R_C_F_gyrofit * R_F_L_DIFOP * R_N_L_current.T
```

这个链条相对当前 `R_C_N` 改变约 0.578°。单前内置 IMU 若仍采用旧的 `Rx(+90°)` 归一化 A，则输入当前 N 点云对应的候选是：

```text
R_I_N_candidate = A * R_F_L_DIFOP * R_N_L_current.T
t_I_N_candidate = A * t_F_L_DIFOP
```

中心 IMU 的位置仍未实际标定；上述旋转公式不会使已有的名义中心杆臂自动成为实测值。

核验 [官方 AIRY 解码器](https://github.com/RoboSense-LiDAR/rs_driver/blob/main/src/rs_driver/driver/decoder/decoder_RSAIRY.hpp)：`decodeDifopPkt` 将 q/t 解码到设备信息；`decodeImuPkt` 对原始轴做量程缩放，而非应用这个 q/t。点云的另外一条 `ENABLE_TRANSFORM` 路径可应用配置和 DIFOP 的 roll/pitch/yaw。此处核验的是当前上游源码，不代表已取得录包时机器上实际驱动构建和全部参数。

本地录包快照中没有足够证据排除额外驱动坐标变换；因此仍然只记录诊断矩阵，**不生成可直接加载的候选 YAML、不修改默认外参**。需要核对实际驱动的输出坐标约定、SN 与话题对应，以及其 x/y/z/roll/pitch/yaw 和坐标变换编译选项后，再批准有版本与来源记录的候选试验。
