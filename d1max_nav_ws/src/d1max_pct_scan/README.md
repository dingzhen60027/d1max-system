# D1 Max 导航会话与规划适配

## 当前主线（2026-10-04）

唯一任务与运动主线是现有 BehaviorTree.CPP 导航图，由
`d1max_pct_scan.navigation_session` 提供公开会话接口，正式操作统一走
`tools/navigation_entry.sh` 的封存版本入口。架构面向室内外、多楼层，
单楼层只是当前测试配置。旧 `single_floor_session` / `single_floor_entry.sh`
是同一实现与旧封存包的兼容名称，不构成第二个任务管理者。
当前 floor-segment 执行合同、楼梯限制和物理验收状态保持不变。
显示只使用一个 RViz：全局/局部在导航面板中切换；局部布局关闭整栋建筑图层，
跟随机身显示滑动地图。不重复打开第二个窗口、不触发重新定位或重新规划。
`planning_only` / `execution`
是同一运行图的两种用途，不是两套上层；PCT/SCAN 是当前可替换的算法后端。
当前状态与边界以[项目 README](../../README.md)及其状态文档为准。

### 系统整改：任务事务、调度与证据一致性（2026-10-04）

本轮修改同一主线，不更换 PCT、原生 SCAN/GridMap、Zenoh 或 SDK 写者，
不以放宽未知空间、扩大近身删点盒或置真验收标志消除故障。

| 边界 | 整改后的合同 |
| --- | --- |
| 手动初值 | 原始 RViz 点击先验证；BT 撤许可并等待旧工作退役及必要停稳，才允许 COMMIT。定位 owner 返回实际应用的 epoch/seed；新身份连续稳定后才接纳新目标。 |
| 消息顺序 | epoch 优先，同 epoch 才比较源时；旧包、重复包、外来包不刷新租约，新 epoch 的源时小幅回退也不能被隐藏或给旧任务续权。 |
| 几何准备 | 参考支撑和跟踪几何分别使用一个 worker、一个可替换待处理槽和一个结果槽；工作线程只读请求，任务线程核验版本、实际接入及期限后提交。 |
| 控制与 SDK | 高频控制不再重建完整样条/索引；SDK steady-clock 唯一 writer 与低频 JSON/发布分离。控制权提交、撤销和最终速度提交保持串行顺序，错过周期不追发旧命令。 |
| 安全采集 | LIO 范围过滤与安全测量回波过滤分开；适配、投影、原生解码及安全入口统一每传感器 100000 点预算。无效回波仍是未知，不生成清空射线。 |
| 停稳与延迟 | 同一哈希记录的 `execution_timing`、`stationary_evidence` 供 SDK、BT、跟踪及安全门控使用。反应范围包含传感器源龄、命令管线、writer 周期和时钟不确定度；旧缺项记录拒绝执行。 |
| 组件存活 | 实际回调进展与传感器有效性分开。host heartbeat + steady 超时监督线程停滞；故障交由原 BT owner 撤授权并 drain，不另建任务或自动重启续跑。 |

## 历史入口：RViz 定位与规划联调（不控制机器人）

Web 的 **“定位与规划”** 是当前统一入口：只负责连接和启停，位姿与目标全部在 RViz 操作。它调用受托管的 `scripts/planning/start_live_planning_view.sh`，与下文的 `scripts/planning/start_pct_scan.sh` 离线模拟入口分开。不启动速度跟踪器、SDK 控制或运动执行，不改原始地图，也不修改通信中间件。

**`start-motion` 显式执行入口** 复用同一定位/规划会话，包含跟踪、碰撞保护与 SDK 门控；这不是当前会话已允许运动。**当前 `per_sensor_rays` 后端仍被执行入口明确禁止，物理验收标志仍为 false。** 普通 `start` 和 Web 默认仅预览。使用前必须阅读 [运动接入与验收边界](MOTION_INTEGRATION.md)，不能跳过保护或把“低速平地”解释成已验收。

工作顺序：**连接传感器 → RViz 初始位姿 → 定位连续确认 → 给目标 → PCT 全局路径 → SCAN 局部样条。** 全局规划从定位得到的当前位置开始，不需要另外设置规划起点。

09-27 按用户要求，默认配置为 `scan_collision_policy: official`：采用官方 SCAN 双圆柱中心查询膨胀障碍；不再要求整个包络有近期饱和自由观测，也不再追加本地 PCT 起点/样条高度否决。未知格仍保留未知数据，不等于实测自由空间；真实膨胀障碍、地图边界和输入断流仍保留。只切换规划判据，不启用 SDK 运动。旧 `observed_free` 模式仅保留供明确选择的离线对照。

### RViz 双布局

面板顶部使用「全局规划 / 局部规划」切换同一窗口，不重启定位、不重新提交目标或计算路线。

- **全局规划**：跨楼层地图、可通行地面、全局路线、3D 目标手柄、机器狗 XYZ 坐标系。
- **局部规划**：跟随机器狗，隐藏整栋建筑和全局地面；显示实时点云、原生滑动占据地图及边界、选中参考段、局部目标、搜索尝试和局部轨迹。全局路线以细线保留。

滑动占据图与膨胀图采用官方 ROS 2 的 Z 高度彩虹色、Squares 显示（含地面），不再统一灰色。
青色框是原生滑动窗口边界。局部最优样条按真实导数速度黄→红着色，附采样点；
颜色不是可通行等级，也不是定位状态。轨迹仍须与同次原生接受结果配对后才显示。
官方发布的这两层是占据与膨胀体素，不是另造的 ESDF 距离场。
每次启动保存同一会话的 `global_planning.rviz`、`local_planning.rviz`，默认从全局布局进入。
仅更新最近一次预览的布局文件可执行 `scripts/planning/start_live_planning_view.sh export-views`；该操作不启动后台或连接机器人。

### PCT / SCAN 接口与验收边界（2026-09-24 官方源码复核）

这条链路不是把两个 `Path` 话题直接相连。PCT 决定楼层、楼梯和全局通路；
SCAN 用实时局部占据图对当前参考段搜索绕行并优化机身样条。
[官方模式及开源集成对照](../d1max_scan_planner/README.md)记录了上游提交和本地扩展，
不能将第三方 Gazebo 演示等同于 D1 Max 实机验收。

| 接口 | 几何含义 | 不能做的替代 |
| --- | --- | --- |
| PCT 全局输出 | 经过支撑与层间连接检查的地面参考线 | 不能当作实时无障碍的机身轨迹 |
| `GroundPathBridge` | 将规划地面估计映射回原定位地图坐标 | 不能用它变形实时点云、机身或发布伪 TF |
| SCAN 参考 | 原路线弧长、拐角与高度；地面到机身偏移只加一次 | 不能另拟合一条削掉楼梯转角的全局多项式 |
| SCAN 输出 | 原生搜索/优化/官方碰撞判据后的候选样条 | 原生 `accepted` 不能绕过代际、时间或成为运动授权 |
| PCT 地面校验（旧严格模式） | 样条中心线下方的有效 PCT 单元及局部高度连续性 | 官方规划模式不追加此否决；它也不是足端或扫掠体积证明 |

表中的地面输出是本项目明确约定的适配接口。官方 PCT 优化器原本输出结合
`reference_height` 与顶空的机器人轨迹高度；本项目从 tomogram 取地面参考后才加
一次机身高度，不能给未经适配的官方轨迹再次叠加高度。当前固定机身高度和
`allow_unobserved` 顶空设置也不构成低顶区域或楼梯足端支撑的实机通行证明。

当前实机会话使用 `per_sensor_rays`：保留前后雷达来源、逐点采集时间及分别运动补偿的射线原点，
以原生地图完成积分的回执确认数据新鲜度；09-27 静止录包已记录到这条支路。
旧 `deskewed_cloud` 后端仍使用合并去畸变云与单一 tracking 原点，只是保留的兼容实现，
不能用其旧说明否定当前逐束接口，也不能将接口接通等同于外参、自体及近身覆盖已验收。
运动安全扫描仍使用 LIO 云、跟踪器仍使用全局里程计，这两项执行前整改未完成，
因此当前仍无运动授权。

09-27 恢复逻辑修复：同一定位轮次的短时失租约立即撤销旧局部路径，但不重设逐束地图的
传感器屏障；观测仍按原源时间过期。原生 SCAN 因里程计未到而拒收参考线时明确回报，
预览桥接请求全局模块重新校验并发布新代次；同一定位 context 在实际轨迹配对成功前，
共享最多 3 次、固定 10 秒的拒收恢复预算，重新规划改变路径形状不会续期。
坐标/几何拒收不自动重试，真正重定位仍严格隔离旧数据。源码及隔离回归完成不代表已部署。

局部样条限速处理区分初态：数值静止初态可保留绕障曲线并拉长时间；运动初态
固定真实起始位置、速度与输入加速度，重新分配时间、拟合并优化内部控制点，
不把实际速度偷偷缩小。两种分支都必须重新通过范数动力学及完整曲线碰撞检查。
当前原生入口没有实测加速度输入，起始加速度仍是 FSM 的零假设，不能称作 IMU 测量。
超过速度上限的初态、有限次重优化不能收敛等情况仍明确拒绝，不发布候选。

启动时将有效 PCT 地面转换成原定位坐标的稀疏索引，绑定原始定位 PCD、tomogram
和索引文件的 SHA-256，存入本次会话。局部回调只查索引，不重读 PCD、不临时加载全图。
旧严格模式会对曲线的空洞、代价阻塞、错误高度带或不连续地面追加拒绝。
当前官方模式保留索引来源绑定，但不执行这项额外否决，不能把预览轨迹当作地面支撑证明。
`ground_support_height_tolerance_m` 和 `ground_support_max_step_m` 是独立配置，
不通过改变实时位姿或偷偷抬高路径来消除错误。

启动时的 `current_floor` 只用于初始视图。每次新规划都用未修改的实时机身 XYZ，
核对两个楼层的原坐标地面高度及明确的机身高度区间；仅有一个支撑候选才确定起始楼层。
楼梯保护区、无支撑或楼层歧义明确拒绝，不能只凭 XY 选最近层。

全局路线显示与执行参考分开：短时数据中断可保留蓝色路线和灰色历史位置，
但不续签旧传感器、旧定位、旧局部样条。恢复后由全局节点重新核对目标与起点，
取消、重定位、地图/会话变化则撤销旧代际。**当前 live 入口仍为无运动预览。**
定位预测、实际步态跟踪、未知区探索和实机碰撞包络标定不由这些显示门控代替。

### 真实 bag 与开源集成复核（2026-09-24 深夜，当前实现）

逐段对照 [legbot_3D_Nav 固定提交](https://github.com/Robot-Nav/legbot_3D_Nav/tree/f60606a4903bad58fca813f76072f9940a284d1d)
的入口、参考线转换、局部目标、优化器和 RViz，而非只复制显示配色。
对方默认使用 Gazebo 真值位姿，并配有运动跟踪器；本入口仍是 D1 无运动预览。
完整结论见[源码对照记录](../../experiments/scan_bag_replay/legbot_integration_audit.md)。

本轮修复的是已复现的软件问题：

- 局部范围采用独立配置 `scan_local_horizon_m: 2.0`。超过局部盒子的真实射线裁剪到边界，
  不再整条丢弃，也不把裁剪终点造为障碍；未知空间仍不能直接当自由空间。
- 非零运动初态不再因为禁止统一缩放时间而一律失败，采用固定边界的有限次时间重优化。
- 低频匹配状态与连续位姿分离。`/d1max/localization/navigation/pose_status` 是轻量高频状态，
  绑定真实输出时间、epoch、初值及有效期；不会通过刷新旧里程计时间制造连续性。
  匹配暂缓不自动删除仍有效的连续位姿；真正超时、重置与硬故障仍撤销局部授权。
- 全局节点复用一个原生工作进程和有界地图缓存；目标代际变化仍丢弃旧结果，
  不通过删减碰撞或跨层检查换取速度。
- RViz 分为定位、全局、局部及调试；参考地图半透明、蓝色全局路径只在显示上抬高，
  当前参考段橙色、局部轨迹绿色、实时障碍红色，并显示原生尝试失败的位置。

真实数据来自 `slam_raw_20260923_010248_eb79d8`，用生产双雷达适配器与 Faster-LIO
捕获真实去畸变点云、同步里程计，再对同一段 35 秒输入做修改前后对照：310 帧里程计、
126 帧点云，保留实测速度，均为隔离 Zenoh、无 SDK 和速度发布。
相同 2 m 前视、0.30 m/s 限速和严格自由空间检查下，最终原生候选从 **0 条变为 27 条**；
通过曲线的采样速度峰值约 0.300 m/s，加速度峰值 0.337 m/s²。
同时修复了旧分支把反向实测速度清零的问题：最终 27 条曲线逐条匹配原始位置与速度，
最大初速误差 `7.22e-16 m/s`（浮点精度范围）。中间一轮的 26 条结果仍保留，但不作为最终边界验收。
这段 bag 的约 19% 初态已经超过 0.30 m/s，不能强制把它们变成合法低速初态。
另测 0.60 m/s 仍有加速度约束重优化不收敛，生产配置没有因此提速或放松验收。

**这项对照只覆盖一楼片段，局部参考取后续录制的 LIO 轨迹，不是 PCT 输出或真值。**
它证明移动边界软件缺陷得到修复，不证明跨层定位、全链路绕障及运动跟踪已经完成。
全局规划另用实际跨层 tomogram 验证：7 m 路线首次约 1.86 s、缓存后约 0.53 s；
83 m 路线首次约 7.80 s（含加载）、缓存后 3.92–3.98 s，路径和楼层选择保持一致。
这些是本机无 profiler 计时，不与带 profiler 的旧报告直接计算加速倍数。
跨层工作进程常驻约 6.22 GiB、峰值约 7.42 GiB；缓存有上限但不是低内存实现。

### 2026-09-24：定位确认误报与输出漏帧

本次查到两个独立问题，不能混为“定位一直在确认”：

- **显示条件混用**：已经完成连续匹配且融合输出有效，却因为外参/时间对齐尚未验收而一直显示“定位确认中”。现在定位预览和实机导航验收分开；同会话、同 epoch/初值且新鲜的定位输出显示“已定位”，验收阻断项单列。真正有未确认种子时才显示“匹配确认中”；融合初始化和初值失效也分别显示。没有把未验证标志设为通过。
- **同频定时器漏取样**：50 Hz 预测输出又被另一个 50 Hz 定时器取最新值，遇到到达抖动会漏帧；此外局部输出去重会误挡较晚到达的全局结果。改为按真实输入回调发布、局部和全局分别去重，全局只取有局部历史支撑的真实 EKF 时间戳。合成回归的同一组 100 帧输入，旧逻辑发布 75 帧，新逻辑发布 100 帧；没有补假帧、重写时间或放宽新鲜度条件。这不是实机稳定 50 Hz 的验收结论。

实机同时存在**上游 IMU 缺口**。17:28 的 15 秒只读采样中，原始 `/front_lidar/imu` 和转换后 IMU 同时出现约 80.001 ms 的源时间间断；2944 个内部源时间戳逐条对应，原始话题的可靠/尽力订阅也完全一致。原 50 ms 硬限反复重置，达到恢复次数限制后停止输出。这解释了为什么偶发短缺帧也要求重给初值，不应把它当成匹配确认没有完成。

按用户要求改为**分级容错**：定位前端和高频传播器都允许真实前后端点支撑的 100 ms 以内缺口，15 ms 以上标记降级、提高不确定性，保留 epoch 与已确认初值；端点估计转角仍不得超过 0.08 rad。超过 100 ms、时钟回跳及真实滤波故障仍保护。没有右端点时，高频预测仍只允许末端外推 25 ms，不伪造 IMU 或连续输出率。界面对有效定位显示“已定位（短时数据降级）”，只看当前同轮次缺口，不用历史最大值永久报警。建图参数、Zenoh、传感器选择、外参和运动禁用状态均未改变。

同步修复定位前端帧尾积分：原来右端 IMU 只用于判断覆盖，实际积分却没有使用它；现在传入真实两端测量，严格在扫描末端截断并保留下一帧所需的真实左尾，避免大缺口下单侧外推或越过扫描末端。此改动只在定位专用分支启用。

### 2026-09-24 工程优化：有界计算与可靠退出

本轮保持 PCT / SCAN 算法、地图、精确时间戳 TF、输入有效性阈值及 Zenoh 不变。Web 仍只启停，初值与目标仍在 RViz；没有启动控制器或连接 SDK。

- **点云处理减少复制**：优化 XYZ 解码、坐标变换和 ROS 消息打包，保留原有采样策略。基准逐字节比较 XYZ 负载，并比较全部反序列化 ROS 字段，结果一致。
- **避免旧点云堵住新点云**：队列最多保留 3 帧，优先处理已获得其采集时刻 TF 的最新帧；无 TF、过期及跨定位代际的帧不能发布。不会拿最新 TF 替代历史 TF，也不积压无限队列。
- **全局规划最多一个原生工作进程**：新目标立即撤销旧路径，异步终止旧计算；旧进程完全退出后才启动新计算。计算使用不可变的起点/目标/地图/定位身份快照。实时点云是否就绪由局部桥判断，不中断静态全局计算；同身份暂时无新鲜位姿时保留计算，但不提交路径。取消、故障、身份变更及超时清空任务。
- **状态不能被迟到消息“刷活”**：同时核验源时间、接收时间和会话标识，拒绝重复、过期及跨会话状态。状态文件原子替换；异常退出保留具体节点与退出码，Web 显示上次失败，不冒充正在运行。
- **清理可验证**：只向本会话拥有的进程组发送 SIGINT → SIGTERM → SIGKILL，记录回收结果；systemd cgroup 作最后保护。残留组未清空禁止重启。修复 ROS 关闭竞态，非关闭状态的真实异常仍抛出。

### 2026-09-24：全局计算与实时输入解耦

实机日志显示原生搜索已经多次找到路径，但定位/点云短暂不可用又取消工作进程并从头加载地图，导致界面反复“计算中”。改为分开管理不可变规划请求、原生计算、结果提交和局部传感器接入：

- 全局计算不等待局部点云；同定位身份短缺数据时撤销局部引用，保留正在计算的请求及已验证的几何结果。
- 提交时必须重新核对新鲜定位、任务身份和起点位移；超过 0.3 m 才重新求解，共享原请求截止时间，不无限续期。
- 局部输入恢复后向全局请求重新核验并签发路径；不在局部桥缓存旧几何或伪造时间戳。用户取消、换初值、故障和任务超时仍永久清理旧任务。
- 界面区分计算、结果等待定位、局部等待数据和超时；提交目标时的提示不再永久覆盖实际状态。
- 全局蓝线仅在 RViz 上移 0.15 m、加宽至 0.07 m，地面体素透明度 0.6；发布给规划器的路径坐标保持不变。

本轮按用户要求不运行额外测试或自动提交导航目标；上述历史验收报告不覆盖本轮新改动。

### 2026-09-24：实时链路与原生绕障修正

- 定位不再要求低频地图校正与高频局部运动同时到达：真实局部新样本驱动输出，历史对齐的 EKF 输入上限 0.30 秒，已验证校正最多保留 0.60 秒；仍受原 ICP 校正 0.75 秒、局部数据与故障门控约束。校正沿用原时间戳并增长不确定性，不重戳旧位姿。新初值、epoch 变化、真实故障立即撤销。
- SCAN 的世界点云与射线起点用同一采集时间精确配对，缓存有大小、等待时间和原始数据龄上限；不再用最新独立位姿误判点云失配。
- 选中全局段被障碍阻断时，先通过原生 A* 得到局部绕行种子，再优化 B-spline；参考代价不再把绕行曲线拉回原来的障碍中。搜索失败明确退出，最终整条曲线都做碰撞和动力学校验。
- 原地重复失败不再 100 Hz 重算同一初值；冷却后依据实际占据变化/机身位移重新尝试。明确区分无绕行通道、优化未收敛、碰撞拒绝、动力学拒绝。
- `/global_path_visual` 仅保存已提交全局路线的显示快照；`/reference_path` 仍是可撤销的局部参考。软暂停不再让整条蓝线闪没，显示保留不等于执行放行。取消、换目标、换初值、故障和请求过期清空两者。
- 黄色参考段、橙色局部目标、红色阻塞点和洋红色绕行尝试是诊断层；绿色必须由同一 plan ID 的已接受结果与样条配对，不能把原地保持样条显示为成功绕障。
- 机器人配置在 `d1max_scan_planner/config/d1max_robot.yaml` 分开记录官方尺寸、文档矛盾及尚未校准的工程假设。没有把总高 0.585 m 当作机身离地高度，没有把最高速度或最大爬坡能力直接当作放行参数。

本轮按用户要求仅做源码审查、必要编译，不运行额外 ROS / 实机 / 自动目标测试。前文历史测试报告不覆盖本轮新改动；不宣称实机避障、楼梯或运动控制验收通过。

PCT 路径 Z 是地面；SCAN 以 `body_height=0.55` 转成机身轨迹。全局机身里程计在 `d1max_loc_map`，局部在 `d1max_loc_odom`，child 都是 `d1max_loc_base_link`；本软件模型中 map→odom 是单位变换。里程计 Twist 为机身系，SCAN 显式旋转成规划系，不能靠重命名 frame 代替变换。

新目标先撤销旧代际；全局规划成功再创建新的 active 代际。旧样条不会复活已取消任务。数据丢失必须重新下目标，不自动恢复移动。短暂原地转向冻结执行进度，SCAN 仍每 1 秒在输入健康时生成新的局部轨迹。
