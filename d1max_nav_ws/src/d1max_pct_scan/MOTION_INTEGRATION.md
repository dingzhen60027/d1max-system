# D1 Max 导航运动接入

## 范围

保留原来的定位、全局规划和局部规划，增加独立执行层：

`RViz 明确开始 → 当前任务/轨迹验收 → 样条跟踪 → 近场碰撞停止 → 运动门控 → 原有 SDK monitor → Move`

Web/普通 `start` 仍只启动预览；初始位姿和可拖动三维目标仍在 RViz 给定。全局规划结果不会自动驱动机器人。新增入口是 `start-motion`，启动后也保持未使能。停止、断流、控制权丢失或任务更换后，不自动续走旧任务。

本次接入的是**低速、平地、同一楼层执行**。跨楼层规划可继续显示，但整条执行参考的高度跨度超过 0.25 m 会被拒绝；不能把每级台阶很小当作允许自动上下楼。仅检查 XY 的“到点”判据已改为包含 Z，并固定每个任务的高度参考。

## SDK 契约

依据本机 RobotSDK-0.1.0-charging_v2-x86_64 的 `sdk_client_api_cn.md`、`sdk_control_ownership_cn.md`、`sdk_callback_cn.md` 和头文件：

- `Move(left_right, forward_back, yaw)` 接收 [-1,1] 归一化比例，不是 m/s；转换顺序是机身 `vy、vx、wz`。
- 本版固定低速档，软件默认 `vx≤0.30 m/s、vy=0、|wz|≤0.50 rad/s`；另保留 1.5 m/s 平面速度硬上限与 MC 实测速度监督。
- API 文档和类型文档的低速映射表有冲突。因此转换实现不等于已验证实际物理速度，`sdk_speed_mapping_validated` 保持 false，等待实机核对。
- 最新 Move 持续 1 秒是厂商描述；本项目选择 20 Hz 发送、250 ms 指令失效保护，不能把这两个软件数值当成已测停止距离。
- `SetMode` 会自动站立；本链路不调用它，也不自动 StandUp、解除急停或重新抢控制权。用户应先独立准备正确姿态/低速通用模式。
- Move 的发送成功不代表实机已经执行。APP 接管优先于 SDK；SDK 丢控制权后停止发运动，不能与 APP 争夺。
- 高频运动反馈继续使用 `OnMcData`，回调内只做快速缓存，耗时工作在回调外执行。

所有运动命令复用一个 `sdk_monitor_bridge` 会话，不新增 SDKClient。四种桥接程序共用进程锁；运动启动和只读启动共用原有 manager 生命周期。运动能力启用不等于运动使能。

## 启动与操作

首次使用本次更新前，旧的会话 manager 需要加载新代码。先由操作者正常停止 monitor 和 Web，再执行 `systemctl --user restart d1max-session-manager.service`；两者都依赖这个服务，不要在运动中重启。此次开发没有替你重启生产服务。启动助手会提前识别旧 manager 并拒绝写入运动启动请求，避免半启动。

1. 如原来的只读 monitor 正在运行，先通过原 manager 正常停止，等进程清理完成。启动工具不会偷偷重启或再开一个 SDK。
2. 在 Foxglove 管理包的 `scripts` 目录，显式运行 `python3 sdk_motion_startup.py start`。它通过原 manager 启动具备运动接口的 monitor，仍为 DISARMED。`check` / `status` 只读。
3. 在导航工作区执行 `./start_live_planning_view.sh start-motion`。保持机器人静止，在 RViz 用 `2D Pose Estimate` 给初始位姿，再编辑三维目标并明确提交规划。
4. RViz「运动控制」面板显示通过检查后，点击「开始执行」并确认。SDK 确认使能后，执行器仍会等待一条新产生的、通过检查的局部样条，旧预览样条不会被重戳复用。
5. 「停止导航」撤销任务和运动许可；重新开始需要重新提交目标。「停止导航」不是硬件急停。关闭 RViz 或执行 `./start_live_planning_view.sh stop` 会清理本次会话的子进程，原 SDK monitor 由 manager 单独管理。

禁止在机器人未独立准备好时强行绕过门禁。当前外参、时间对齐、机身高度、碰撞包络和速度映射的未验收标志均原样保留。RViz 显示的阻塞原因是待完成的实机验收条件，不是需要随手改成 true 的开关。

离线准备：`./start_live_planning_view.sh prepare-motion` 只生成会话配置，不连接 SDK、不启动任何节点、不发送运动。

## 执行与失效规则

| 边界 | 执行规则 |
|---|---|
| 全局路线 | 使用已被桥接器接受的 `scan_reference` 代次，不拿全局 worker 的另一套代次混用 |
| 局部轨迹 | 原始 TaggedBspline 与同 ID 的 accepted debug、地面支撑、当前定位身份同时通过；Marker 不具有执行权限 |
| 跟踪指令 | 使用 tracker 状态内同任务/同轨迹的速度，不把无代次的旧 Twist 直接转发给 SDK |
| 样条重规划 | 未配对的新候选先零速等待；完整配对后，只有原生重新确认旧曲线无碰撞且证明仍新鲜，才允许有界交接；不能把旧轨迹心跳当成安全证明 |
| 冻结反馈 | 执行协调者是唯一发布者；未使能时冻结 SCAN 的执行时钟，执行时才转发真实跟踪反馈 |
| 停止/数据恢复 | 撤销门控，尽可能发送零速；数据恢复、APP 退出或 SDK 重连均不会自动恢复旧运动 |
| SDK 端 | 校验独立 arm generation、序号、会话、来源、时间戳、机器人状态、急停及 MC 新鲜度 |

Humble Collision Monitor 原生在持续零速超过 `stop_pub_timeout` 后不再发布零速，见[官方源码](https://github.com/ros-navigation/navigation2/blob/humble/nav2_collision_monitor/src/collision_monitor_node.cpp)。执行入口使用独立的薄适配器，让每条新输入仍经过原生碰撞检查并输出结果；没有新输入就不发布，不通过定时器伪造已检查的速度。原 Nav2 入口不受影响。

## 验证边界

单元测试、Qt 离屏面板测试、隔离 Zenoh 的虚拟 SDK 协议测试只验证软件链路。它们不证明真实机器人刹停距离、外参精度、定位鲁棒性或楼梯执行安全。本轮没有连接机器狗，没有自动起身、切模式、解除急停或真实 Move。

2026-09-26 已完成：真实执行协调器/跟踪器/门控的隔离接口检查 21 项通过（SDK 为本地虚拟服务，碰撞在该测试中明确为透传）；原生碰撞库独立验证 6 项通过；RViz 工具包离屏测试 60 项通过。门控、启动管理、桥接准入和单楼层跟踪器的组件回归均通过。测试私有进程已退出，未切换通信中间件。

## 2026-09-26 系统审查后的修复

这一轮针对执行链路修正，没有更换定位、全局规划算法或 Zenoh，也没有把未验收项设为通过。

1. **SDK 租约和撤销顺序。** 新命令到达时先检查上一条命令的 250 ms 租约和使能后的 600 ms 首包窗口，再更新接收时间，避免迟到包掩盖失效。最终状态检查和非阻塞 `Move(..., 0)` 提交共享串行边界；SDK 回调只写轻量邮箱/原子撤销标志，避免回调重入锁死。失效后不能靠后续命令自行恢复使能。已经提交给厂商库的命令不能撤回，不应把软件互斥理解成物理瞬停。
2. **跟踪和换轨。** 有效新样条先完整校验，再原子替换并保留前向/转向加速度历史。进度跟随实测投影，不依靠墙钟推进；每次只搜索有界前视段。D1 Max 当前不横移，因此横向偏差反馈转换为转向修正，不再直接丢掉横向分量。无效、过期或撤销仍立即零速。
3. **有证据的异步交接。** 新样条和对应调试验收来自不同话题，单边到达即报告 `handover_pending` 并零速。完整新验收可携带旧曲线 ID、原始碰撞复核时间和结果，只有同代且证明龄不超过 0.15 s 才允许短暂交接；首次 pending/错配起的总等待预算也是 0.15 s，不能靠新候选或心跳续期。复核最多 5000 次查询/8 ms，预算不足按无证明处理。不能用后来的心跳刷新原始轨迹或检查时间，也不承诺任意消息延迟下都无顿挫。
4. **统一低障碍几何。** SCAN 与安全扫描从同一个机器人配置读取范围。机身参考高度暂取 0.55 m，地面排除带暂取 0.10 m，向下碰撞范围因此为 0.45 m；安全扫描下限为机身坐标 -0.45 m。体素碰撞按实际查询高度计算，避免额外一层体素将地面当障碍；缓存键包含上下高度范围。0.10 m 是待验证工程假设，不代表更矮障碍一定可跨越；稀疏/窄小障碍仍受点数和观测范围限制。
5. **重定位与地图重置。** 定位身份发生变化后，桥接请求原生清理占据、已观测自由空间、膨胀和待配对传感器缓存；收到匹配回执后才放行新数据。重置屏障同时覆盖此前接收和发布的时间戳，防止跨话题延迟旧云重新进入新图。同一定位身份下的短时断流保留历史内容，但不保留虚假的新鲜度。
6. **恢复和到达判据。** `WAIT_ENVIRONMENT` 在实测速度恢复可行时也可触发有界重试。到达必须看实测 XY 和 Z，不能因样条时间走完而误报完成。
7. **计算负担。** 地图可视化默认从 20 Hz 降为 3 Hz，并按地图修订号复用结果；没有降低传感器处理或规划频率。跟踪搜索不再随整条样条时长增长；旧曲线交接复核也有明确预算。这是工作量约束，不是 NUC 实测性能承诺。

以上模块的原生库/消息定义已变化，下一次启动必须使用同一批重编译产物，不能混用旧进程和新接口。本轮不主动重启生产服务或使能实机。隔离合成场景与运动接口检查只能证明软件契约；真实双雷达原点、外参/时间同步、速度映射和实机碰撞包络仍需单独验收。
