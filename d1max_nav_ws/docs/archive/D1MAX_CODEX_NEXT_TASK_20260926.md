## 5. 上层架构：保持算法，统一边界

建议目标结构如下。第一轮仅补可观测性和契约检查，不一次性迁移所有坐标或拆出大量新节点。

```text
原始定位 PCD ──→ 独立规划处理副本 ──→ PCT 地面参考路线
                                          │
                                  显式地面映射适配
                                          │
                                  有界局部参考段
                                          │
双雷达、IMU ──→ 定位估计 ──→ 连续局部位姿 / 地图校正 ──┐
       │                                                 │
       └──→ 逐点时序与双源原点投影 ──→ 原生滚动地图 ────┤
                                                         ↓
                                               SCAN 候选机身轨迹
                                                         ↓
                                    碰撞 + 支撑 + 动态边界 + 数据时效校验
                                                         ↓
                                    现有执行协调器：人工授权、任务、SDK 状态
                                                         ↓
                              连续里程计系跟踪（须完成带版本坐标适配）
                                                         ↓
                              独立近场保护（须完成可靠感知支路接入）
                                                         ↓
                                       运动门控 → 唯一 SDK monitor
                                                         ↓
                                       实际运动与 MC / 定位反馈
```

### 5.1 不能混淆的三个问题

- **环境证据：** 这个体素是否被观测、观测到了什么、源时间是什么。占据、自由、未观测和证据冲突是环境事实/不确定性。
- **规划可行性：** 当前或候选机身包络是否会碰撞、下方是否有地面支撑。机器人自体与外部障碍必须区分，不能用一个带余量清空区代替。
- **执行许可：** 当前轨迹是否属于当前任务、有效期是否尚在、人工是否授权、控制接口是否准备好。这由现有执行层负责，地图或 RViz 不发运动许可。

### 5.2 必须保留或收敛的契约

1. 原始定位地图与楼层修整后的规划地图不假装为同一个刚体坐标系。地面参考做专门映射，实时点云和机器人位姿不做非刚性扭曲。
2. PCT 路径是地面参考；SCAN 是机身参考。地面到机身高度只加一次，并绑定几何配置版本。
3. 定位会话/轮次、地图重置序列、参考任务代次、轨迹 ID 分别保留，不能用一个 generation 混代所有身份。
4. 轨迹准入需绑定生成时的实际输入证据、坐标校正信息、几何配置、任务代次和原始有效期。已有字段直接复用，缺失字段再补，不给每个模块另建一套不相容状态。
5. 局部控制转换必须同时转换轨迹及其状态参考；不能只把 global odometry 换成 local odometry。建议使用明确时刻/版本的地图—里程计变换对轨迹锚定，校正超出剩余安全预算或重定位时撤销并重新校验。
6. 新消息到达、整个地图的新鲜时间、机器人即将进入区域的最近真实观测时间是不同概念。关键区域证据不足必须可说明，不能由远处的一次新观测续期。
7. 现有唯一 TF 发布者、唯一 SDK 会话和执行协调者保持唯一。

## 7. 阶段 B：实现“起点为什么不可行”的完整诊断

### 7.1 复用生产实现

扩展原生 `inspectInflateOccupancy` 或共享其相同枚举/碰撞几何，实现只读详细查询；在 `offline_projected_rays_probe.cpp` 增加受限导出接口。不得用 Python 重新近似双圆柱，再把与生产行为不同的结果当作解释。

### 7.2 输出字段

一次完整诊断至少包含：

- 查询源时间、执行查询时间、session/epoch/seed/context sequence、地图修订号、两源实际积分序号和源龄。
- 机身位姿与完整姿态；实际查询使用的 yaw；上下包络、两圆柱中心/半径及配置哈希。
- 查询区域每个**唯一体素**的全局整数索引、体素 AABB、原始 log-odds、原生查询状态、命中哪个圆柱。环形缓存地址不能作为跨滑动窗口的唯一身份。
- 原始重叠计数和去重计数同时输出，不能直接比较两套不同口径后声称阻塞减少。
- 诊断类别至少区分：确定占据、已达到自由判据、从未观测、已观测但证据不足/冲突、地图外、非法数值。规划状态仍维持当前策略。
- 能追溯时输出最近命中/穿越的源编号、源点索引、ring、采集时刻及射线起终点。追溯不到时明确缺失，不反向猜测来源。
- 体素在机身坐标的位置、相对实测地面的高度、是否与已核实实体自体相交、是否落在安全余量区。没有实测地面或自体模型时标记 unknown，不用配置假设冒充测量。

可增加近身有限区域的诊断旁路，保存有界的最近射线来源记录；默认关闭完整明细，限制记录数量、频率和内存。不要给全图每个体素无限保留点云历史。元数据过期、地图滑动、重定位和缓存复用必须正确清除或版本化。

### 7.3 必须回答的问题

1. 当前 occupied 体素对应哪一个实际原始回波？属于地面、自体、外物还是仍无法判断？
2. unknown 中从未观测与证据不充分分别有多少唯一体素？各自在哪里？
3. 实测 base_link 高度、地面高程和碰撞包络底面是否一致？体素完整 AABB 是否确实与包络相交？
4. 两雷达是否真正有射线覆盖待查询区域？射线是被自体遮挡、物体遮挡、量程/视场限制，还是在转换/配对过程中丢弃？
5. 前方约 2 米查询通过而机身起点失败，差别来自几何、可观测性还是证据累积？
6. 是否存在未达到 occupied 阈值的命中/冲突证据，被简化日志一律称为“未知盲区”？

### 7.4 可视化

保留双布局、固定 RGB 机身坐标轴。在局部诊断层增加独立开关：原始回波、各雷达原点和抽样射线、实测地面、实体自体、含余量碰撞包络、占据、未观测、证据不足、候选轨迹与已验收轨迹。

所有同屏诊断必须采用一致时间/坐标/版本；显示裁剪要注明。不同颜色只表示诊断类别，不修改碰撞数据。失败尝试不得绘制成可执行路径。

## 8. 阶段 C：只修复已有证据支持的原因

不要在拿到诊断前预选“过滤腿部”或“放开未知空间”作为答案。

### 情形一：坐标、时间或原点错误

修正变换/插值/时间转换本身，保留两源独立原点与原始点时间。同一扫描采用一致地图校正，起终点使用同一变换。增加旋转和杆臂场景回归，证明修复前失败、修复后通过。不要改 LIO 参数补偿感知支路错误。

### 情形二：地面与包络相交

先取得站姿下实际参考点和地面的关系，区分总高度、base_link 高度、传感器高度与负载高度，再判断是物理参数错、体素化接触还是低障碍真实存在。不得简单提高地面排除阈值，也不能据此宣布阈值以下障碍可跨越。

### 情形三：已证实的自体回波

固定机身、NUC/支架等刚体可独立标定；与实测姿态同步后再评估最小实体自体过滤。动态腿部没有可靠关节/姿态来源时，不能按名义站姿过滤实际运动中的腿。

自体过滤区域不得等于带余量的碰撞包络。删除已证实自体命中后，不能把其后方射线继续延长并清空遮挡空间。仅能在确有证据和几何误差约束下，对当前实体内部的查询作专门解释；该解释不能迁移成未来轨迹的自由空间证据。

### 情形四：真实不可观测空间

如包络外部、安全余量或即将进入的区域确实不可观测，明确记录为传感器可观测性/布置限制。给出需测量或调整的最小区域与原因。不得通过局部清空、历史低概率或虚拟边界直接放行。必要时提出传感器安装调整/补充近场感知的独立验证任务，而不是无限调参。

### 情形五：概率累积策略不适配

只在逐射线证据可解释时研究独立 free 阈值、冲突状态和近场观测有效期；仍保留“未观测不等于自由”。与基线做单变量对比，并测试命中与穿越冲突、低矮/细小障碍、遮挡和旧自由空间。不得凭成功率调低安全判据。

涉及上述情形的物理事实无法确认时，停止该项行为修改，保留诊断结果和明确的人工补充项；其他纯软件诊断/时序工作可以继续。

## 9. 阶段 D：完整时序、地图历史与执行接线审查

### 9.1 统一时间线，但不合并不同时间概念

对真实录包记录：原始 IMU/点云源间隔、接收间隔、LIO 后验时间、预测目标时间、实际位姿发布间隔、地图校正源龄、投影等待和耗时、每源实际积分时间、桥接收到积分通知时间、轨迹源时间和原始租约、具体撤销原因。

诊断必须区分历史版本已修通知缺陷与当前版本尚未复验。不得把旧的“位姿有效但路径被撤销”记录重新包装成新版本仍复现。

### 9.2 新增两类潜在风险回归

- 同一 epoch/seed 下连续的小幅地图校正：每步未超门限但累积可超过一个体素，检查旧障碍、旧自由空间和新投影是否产生错位。用试验证明风险大小，不预设已经造成当前起点问题。必要时再选择连续 odom 中局部建图、分片重建或有界一致性撤销方案，第一轮不要直接全面迁移。
- 数据流仍新鲜但待行区域长时间未被射线覆盖：检查新到达的远处数据是否会被误当作该区域的新证据。过期只能降为待确认，不能自动清成自由。动态环境中的区域有效期是待设计/验证的策略，不是假定当前已支持。

### 9.3 执行前整改设计，不启动执行

- 说明安全扫描如何从可靠近场输入生成，并与规划支路共享几何、时间和来源契约；保护功能独立于轨迹优化结果。不得继续把 LIO 稀疏/近距筛选后的点云当作未经验证的完整近身安全输入。
- 检查 tracker 当前 global odometry 接线与连续 odom 控制目标的差异。提供含真实时间与校正版本的轨迹适配方案，不准只换话题。构造机器人静止、只有全局校正变化的测试，检查是否产生不可解释的控制突变。
- 检查安全扫描上下高度范围、点数门限、停止区、多传感器断流和转换失败是否保持明确语义。平面投影保护不是完整三维碰撞或硬件急停。
- 增加原地转向/航向调整时的扫掠包络验证；路径切线航向的碰撞通过，不自动证明机器人从实际朝向转到该朝向的过程安全。
- 保持现有 TaggedBspline、对应 accepted debug、支撑验收、人工任务与 SDK 门控的配对/失效规则。

## 10. 回归矩阵与通过条件

必须同时有“该通过时通过”和“该拒绝时拒绝”。真实录包、解析几何场景、消息时序模拟三类证据分开报告。

| 场景 | 预期与核查重点 |
|---|---|
| 原真实录包诊断基线 | 同一输入/配置下诊断不改变原查询结果；逐项解释与交接统计差异 |
| 实测空场静止 | 在有效且完整证据覆盖的周期，起点合法并可生成有效短段；如果证据不足则解释拒绝，不能伪造通过 |
| 实际障碍与可见绕行通道 | 生成绕行且独立几何检查通过；绕行不能进入未观测区域 |
| 脚边外物、低障碍、细杆 | 自体过滤不吞掉外物，地面排除不隐藏应当阻挡的低障碍 |
| 自体遮挡 | 去掉自体命中不制造其后方自由空间；实体外的未知保持未知 |
| 地面体素边界 | 接触关系按完整体素及实测几何核对，不靠少查一层体素漏检 |
| 未观测与冲突证据 | 诊断分开；严禁通过 legacy 的“未占据”查询绕过严格判据 |
| 通道封堵/遮挡未知 | 不输出已准入轨迹，给出清晰停止/等待原因 |
| 一源断流、另一源继续 | 另一源或心跳不刷新失效源，不使用过期证据 |
| 延迟、乱序、重复、旧代次 | 不重新积分为新观测，不复活旧轨迹，旧消息不撤销较新有效任务 |
| 滑动窗口与重定位 | 无缓存串格/旧索引复用；新定位身份正确清图并等待真实输入 |
| 小幅累积地图校正 | 不把旧地图与新校正误差隐藏为稳定定位；不产生无解释控制突变 |
| 移动状态换轨 | 实际非零初速度/加速度边界保持，不能用静止起点测试替代 |
| 原地转向与急转 | 校验真实转向扫掠区域，不仅检验位移路径上的切线姿态 |
| 取消、换目标、失效恢复 | 撤销执行许可；恢复只接受新的当前任务轨迹，不自动续走旧任务 |
| 独立安全支路 | 自体、低障碍、断流与时间变换的判据可追溯，失败能传递至门控 |

先列出具体将执行的测试目标。不要直接运行可能隐式拉起生产 Domain 的整个 CTest 集合。涉及 ROS 的测试先验证隔离及无 SDK/控制出口；Ran 0 tests、纯透传碰撞或虚拟 SDK 不能算作对应实机能力通过。

## 11. 本轮之后的里程碑

### M1：近身证据闭环

交付逐体素诊断、根因分类、已证实的软件修复和正反例回归。物理缺项单独保留，运动仍关闭。

### M2：物理几何与定位连续性

经单独授权再安排被动采集和实测。标定机身参考点、传感器外参、载荷、自体实体与碰撞余量，复验静止/移动/转弯/断流恢复。动态腿部模型需要真实同步数据或另行验证的保守模型，不能伪造关节状态。

前端下沉单独使用固定 bag、二进制和参数，关闭回环影响做单变量试验。检查输入外参、时间单位、真实 IMU 消费、运动激励与估计残差。回环拉回不等于前端修好，原地图地面处理不等于通用校准。

### M3：NUC 被动整机预算与软件执行联检

在首次自主运动前就检查目标 NUC 上定位、感知、规划和所需显示/录制同时运行的资源与延迟；不把 NUC 预算全部拖到上楼之后。记录冷/热启动、不可达搜索、连续换目标的内存峰值、延迟分位数和最大间隔。实际部署和启停仍另行获得授权。

开发机 global worker 的 2.75 GiB 常驻或约 3.58 GiB 初始化峰值不是整机内存预算；开发机投影/积分 P95 不是安全最坏延迟。硬件不同的 `-march=native` 产物需重新构建。

### M4：经授权的低速平地闭环

先独立完成受控 SDK 比例—物理速度标定与停车链路验证，再在条件通过后验证平地导航。Move 输入顺序和归一化尺度必须与实际 MC/位移反馈一致，不能把规划 m/s 直接作为比例。

实测停止距离需覆盖感知、排队、计算、传输、SDK/执行器及制动过程。不能将规划加速度 0.35 米/平方秒当作实际可用制动能力，不能用平均延迟代替安全裕度。无现场授权、清场和独立停止保障不得开始。

### M5：跨层执行与更复杂恢复

单独验收楼梯模式、俯仰横滚、腿部扫掠、支撑区域、净空、楼层关联与失败恢复。当前同层执行的高度跨度门槛不是楼梯通行许可证。

虚拟边界脱困为后续独立能力；虚拟层只可引导搜索，不可作为可执行自由空间。不能拿脱困模块解决起点自体/未知错误。场景理解和机械臂任务以后接在任务层，不进入当前安全许可捷径。

## 12. 必交付成果与汇报格式

建议实验目录内生成：

- `baseline.json`：源码、运行产物、配置、地图、录包与基线版本。
- `effective_parameters.json`：最终参数及覆盖来源。
- `query_timeline.jsonl`：逐次查询时间、身份、原始/去重计数、拒绝阶段。
- `query_voxels.jsonl`：有界逐体素证据与来源；未观测不能伪造射线来源。
- `time_contract_report.json`：源间隔、接收间隔、处理与撤销原因。
- `regression_report.json`：逐案例期望、结果、输入、失败样例、隔离方式。
- `root_cause_report.md`：已确认原因、排除依据、未确认原因、最小修复前后对照。
- `architecture_decisions.md`：控制坐标、安全感知支路、规范支撑几何与渲染分离的决策及迁移顺序。
- `physical_validation_checklist.md`：用户只需提供/测量什么，哪个环节必须另行授权。

产物路径为本任务建议，不代表现在已经存在。大体积原始数据不提交 Git；给出明确可复制的离线复现命令及所需环境，命令必须实际验证，不杜撰工具参数。

最终汇报按以下六项组织，不累加历史测试装作本轮成绩：

1. 实际审查和执行了什么；使用的真实版本是什么。
2. 起点受阻中确定占据、从未观测、证据不足各自的空间来源。
3. 哪个原因已证实，做了哪一处最小修复；是否仍有未解决原因。
4. 修复前后同输入的行为，以及危险反例是否仍正确拒绝。
5. 尚需的物理输入/授权，不把猜测写成厂商结论。
6. 当前是否仍保持无运动，以及是否发生部署/提交；本轮默认均不发生。

本轮完成的标准不是“终于画出一条绿色曲线”，而是：**这条短段为什么允许、另一条为什么拒绝，都能追溯到同一时刻、同一坐标、同一机器人模型的真实证据。**
