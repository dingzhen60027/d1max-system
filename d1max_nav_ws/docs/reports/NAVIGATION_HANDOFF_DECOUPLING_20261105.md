### 现场事实

2,311 个运行成员与会话记录一致。前两个任务到达；第三个上楼任务在

这是 SCAN 对正在使用的曲线返回 `occupied`，不是地图证据期限、SDK 断开或 BT 结束。
该任务此前还有可恢复的短时零速事件，不能将此处写成整次任务的第一次零速。

持续停止时机身源龄 19.1 ms，整次任务控制间隔最大 50.261 ms、机身源龄最大
48.962 ms。新参考 `300` 已接收，前向窗口仍有约 3.44 m，SCAN 后续继续求解；
跟踪器却反复拒收 `curvature_braking_limit_below_current_command`。
11:19:29.811 用户手动接管才取消任务，不能倒果为因。
这段持续停止期间有 255 轮 `NativeSolve` 和 251 条 `SOLVE_WORKER_ACCEPTED`，
并非简单提高规划频率就能解决；SDK 断流记录比取消还晚约 222 秒。

### 已修复的两处通用时序问题

1. **中断恢复依赖旧曲线重新有效。** 原先输出暂停后恢复了暂停前的命令历史，
   只有旧曲线再次通过 SCAN 才按实测状态修正该历史。即使机器人已停，新候选仍按
   原来的约 0.28 m/s 判断能否接入，造成“旧曲线不安全，新曲线进不来”的循环。
   现在新候选经 SCAN 接受、收到中断后的新鲜实测状态后，先复用原有实测边界恢复逻辑，
   再执行接入。两阶段提交等待 ACK 时只恢复旧几何，不回滚新的实测控制历史。
   正常换轨不进入此分支；零指令不被当作实测停稳；尚有效的实际发送边界仍保留。
2. **楼梯参考和支撑数据异步到达。** 原先参考先到时可能短暂用直立机身检查坡面，
   把输入未齐误报为占据。typed 楼梯/混合窗口现在只在同版本、同坐标系的支撑几何到达后
   才进行候选目标查询；缺项进入已有可恢复重试，不清除当前轨迹、不取消任务。

| 规划 owner | 调度、完成结果回收、候选交付 | 无地图也能退役取消/过期结果；成功结果仅保留一个待准入槽 |
| SCAN 原生裁决 | 当前轨迹和候选的环境判断、换轨证据 | 候选失败不抹除当前轨迹；真实碰撞立即约束输出 |
| 跟踪器 | 实测进度、当前已提交曲线、速度限制器历史 | 普通换窗/换轨不将速度与加速度历史归零 |
| SDK 唯一 writer | 命令发送、控制权、急停、原命令期限、实际发送事实 | 不运行地图检查；不复活旧任务命令 |

**区分计算慢与证据失效。** 求解未完成、地图槽暂忙、显示发布慢，不应被当成任务失败或清空轨迹。
但真实输入/状态超过其原有效范围、碰撞、取消或失权，仍不能用旧数据伪装连续运行。

## 本轮修复的交接缺陷

1. **接收不再排在融合之后。** 原投影订阅、解码、融合、快照和状态发布同属一个 writer 回调链。
   已有的双源 latest 槽只能在 writer 空闲后更新。整改为独立串行接收、固定双源邮箱和唯一地图 writer；
   接收侧不积分、不改融合定时器、不发布快照。定位身份切换前后都核对 token，防止旧坐标批次晚到。
   用一个可合并的 GuardCondition 唤醒原 writer，不新增固定轮询延迟；融合过程中收到的新通知保留到下一轮。
   首次接收时间与进入 writer 配对等待时间分别保存，前者不重签，后者不能误计上一轮融合耗时。
2. **结果回收不依赖地图槽。** 原 FSM 在回收 ready future 之前先借地图；地图忙会拖延取消和结果退役。
   现在先回收一次，成功结果保存在固定一槽，仍使用原求解预算；只有真正几何准入才借地图。
   失败或取消不清当前轨迹，不重新分配期限，也不启动第二个并发求解。
3. **候选准入取得已完成的新地图。** 原融合结束时没有候选，之后候选到达可能继续借旧 solver 槽。
   现在由原 writer 按明确需求交付已完成地图；准入绑定有限的完成版本，不追逐每次更新而饥饿。
4. **发送回执按任务/授权代际去重。** 原任务内发送序号重置，但反馈端沿用上一任务的高水位，后续任务收不到反馈。
   现在按 SDK 会话、授权代际和任务身份区分；新任务第一条反馈立即可达，迟到旧任务不能覆盖它。
   此缺陷也存在于前一版本，不能单独解释本次退化。

另保留一次等价的射线遍历局部优化：不改射线顺序、计数、占据、源时和步数预算。
完整地图事务上的改善远小于单一热循环，不能把微基准百分比当作整机卡顿已消除的证据。

## 验证方法与边界

本轮主要检查事件顺序与所有权，而不是根据某次耗时反复调参数：

- 地图 writer 被占用时，前后雷达仍能分别更新各自最新批次；冻结中的批次不被改写。
- 新定位身份开始后，旧 in-flight 解码结果不能进入新地图；乱序、重复和单源断流不刷新源时。
- 求解完成、取消、新参考、地图槽释放以不同顺序到达，不重复消费、不丢任务、不复活旧结果。
- 候选在融合完成之后才到达，也能取得完成地图；不能无限复制同一个版本。
- 新任务发送序号从 1 开始，回执仍可达；旧授权和旧任务反馈不能污染新任务。
- 原生产 GridMap 的占据、自由证据、原始射线与楼梯查询保持一致。

源证据断档仍是必须诚实保留的验收项：历史日志没有完整保留本次原始点云执行流。

结构修复与软件验证不能替代新版本实机连续行走的验证；本报告不声明“所有 bug 消除”或“任何情况下不停车”。
