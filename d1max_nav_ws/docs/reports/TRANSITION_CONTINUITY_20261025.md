# 滑动窗口、换目标与楼梯段交接：离线连续性修复

日期：2026-10-25。范围：真实软件组件的离线时序验证与默认包同步；不连接机器狗，不启动生产导航、RViz 或 SDK，不发布初值、目标或运动命令。

## 结论

本轮以正在选择的默认包 `39e8cc7131c13c54a0da279555338667b30fcc9d725fa977c4742482c62aa710` 为基线，不以 Git HEAD 代替部署事实。完整核对 10,349 个封存成员后，确认并修复三处交接错误。

| 环节 | 同输入修复前 | 修复及不变项 |
|---|---|---|
| 平地→楼梯、楼梯→下一段 | 旧段位置投影失败会阻断新段接收同一真实位姿；提交迟到后，新段没有出口穿越证据，卡在等待参考 | 当前段与候选段分别处理原始位姿；保留真实源时间、单调去重及各自异常。没有伪造进度、换段证明或新鲜数据 |
| 坐标锚硬替换与换轨 | 旧候选已清理，但其 prepared 预约仍存活，迟到 commit 能越过新参考边界 | 只退休硬替换对应的旧预约及精确匹配的待提交指令；保留正在执行的轨迹。普通滚窗、已分类楼梯连接不进入此新分支 |
| 连续换目标 | Action 发送同步异常被误记为 terminal：Compute 可能过早放行下一任务，Follow 可能无限等待清理 | 保留失败结果，但不伪造退役；真实拒绝/终态正常排空，迟到句柄定向取消。无回复沿用原取消超时，明确结束等待，不新增永久故障锁 |

这三项是可重复的软件缺陷，不代表已证明它们解释所有历史实机停顿。永久断链仍需退出并清理会话，不能凭空确认旧工作已停止。
