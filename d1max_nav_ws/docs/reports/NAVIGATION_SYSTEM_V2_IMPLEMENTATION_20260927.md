## 当前结论

**这是开发态的软件重构批次，不是跨楼层自主导航验收版本。** 已修改真实工作区源码、构建隔离二进制并执行组件回归；没有部署到生产安装目录，没有连接或重连 SDK，没有发送 SDK 运动命令，没有 push。通信仍为 Zenoh。早期扩大 Python 测试范围时出现过历史测试的 ROS 图隔离问题，详见下文，不作“全程没有创建任何 ROS 节点”的声明。

## 2. 本次实际实现

### 单一任务与生命周期

保留 BehaviorTree.CPP 导航器，引入真正的 LifecycleNode、bond 和 Nav2 生命周期管理。配置完成前不接目标，失活先进入异步 drain；依赖仍存活时等待旧 action/reference 退役，再关闭下游。软件退役与物理停稳分开，不把取消 ACK 当成“已经停稳”。

`Navigate / ComputeRoute / FollowRoute` 升级 schema 2。目标接纳有 reserve/commit 屏障；取消、重新初值、生命周期切换之后到达的旧计算不能复活。执行确认绑定 `task_id / route_id / route_hash / request_id`，预览及未验收路线始终不返回运动许可。

RViz 目标通过 Navigate Action 提交；拖动仅改草稿，可选终点朝向，执行确认保持幂等身份。目标/执行服务等待有单调时钟期限，超时如实显示未知；迟到的旧确认不覆盖新目标/取消状态。关闭显示端不取消任务，核心死亡仍由任务/执行门独立处理。

源码：`d1max_navigation_bt`、`d1max_navigation_bt_interfaces`、`bt_configuration.py`、`lifecycle_shutdown.py`、`live_view.py`。

### 完整路线与原始地图

`RouteSnapshot` 固定地图哈希、任务/路线身份、地面 XYZ、楼层、楼梯、平台、入口出口、方向和所需能力；`Path` 只用于兼容/显示。适配器唯一发布完整 `RouteReference`，桥接入口不再从任意显示 Path 建立任务。

使用原始地图支撑场对经过非刚性处理的规划路线回投，不发布假 TF、不变形雷达或机身。真实地图检查包含双向语义和源地面支撑；几何证明不完整时只允许预览。一次支撑最近距离为 0.121089 m，略大于当前 0.12 m 查询半径；这不是已证实的障碍，也不是通过放大阈值即可获得安全证明。

修复三层时间去重中的取消丢失：使用整数纳秒与显式 delivery sequence；同一仿真时刻的合法取消/新任务可以退役/接纳，旧所有者取消不能清除新任务。消息源时间没有被重打时间戳。

源码：`source_route*.py`、`route_ingress.py`、`bt_adapters.py`、`live_scan_contract.py`。

### 定位与坐标锚

定位发布器从**同一次有效输出**构造 local/global 机身里程计对，携带真实 epoch、seed、地图版本、输出时间、后验时间、IMU 时间和传播时长。跟踪器消费 typed local state，不再把全局地图校正直接当作控制运动。

连续参考核心按当前路段有限 XYZ 搜索；允许小幅实测倒退，确认进度不倒退；普通累计地图校正生成候选锚，不移动已接受曲线、不重置路线。硬 epoch/seed 变化隔离旧任务。地面点与机身点用 `point_reference` 明确区分；body_center 输入要求 SCAN 高度偏移为零，防止重复补高度。

原始双雷达逐束投影核心支持连续 odom，普通累计校正超过 10 cm 不再锁死 odom 模式地图；逐束原点、端点使用采集时刻的局部状态。该模式目前是显式可选核心能力，**尚未成为整条运行链默认模式**。

二楼初值可选对应楼层支撑场，不再固定一楼 Z；“约 50 cm”没有被当作精确外参写入验收标志。

源码：`navigation_output.py`、`navigation_wire.py`、`continuous_reference*.py`、`ray_projection.py`、`live_ui_contract.py`。

### 原生 SCAN 与跟踪

继续使用生产 GridMap、A*、B-spline optimizer 和碰撞查询；没有用简化地图替代。一个写者维护地图，固定三槽原生只读快照不覆盖读者，每个求解器私有查询缓存。单在途 worker 异步求解，旧 generation 的结果不会提交到新任务。

搜索、优化、重试、验证共用 400 ms steady-clock 截止；不能内部失败一次就续一份预算。候选失败不代表在用曲线失效；仍需最新感知和当前接入验证才能继续使用旧曲线。全局资源启动预热，默认全局请求 10 s 超时；原生搜索毫秒数不冒充端到端性能。

跟踪核心按实测位置推进，保留换轨前速度限制器历史，不以墙钟假装机器人沿曲线前进。局部曲线进度与全局确认路线进度分别定义。

本批次交叉审查又发现移动候选仍被旧起点 2 cm 接口拒收，以及最终碰撞检查耗时后源龄可能已经失效；修复及原生测试以 `native/NATIVE_V2.md` 为准。接收/地图融合线程调度仍需进一步拆分，不能把定时器设为 20 Hz 就宣称达到 20 Hz。

### SDK 合同

新增无网络的模式事务和停稳验证核心：停稳→单次切换→ACK→新状态确认；超时/状态不明/失权不盲目重发。MC 采用真实源时映射；无厂商源时的状态回调明确使用会话内序号和接收时刻，不能伪称原始测量时间。楼梯 Move/保持未验收时不能签发可执行模式。

这些是可测试的状态机，**不是已经接通机器人控制链**。唯一会话写入、硬件失权/断网停止和物理停稳阈值仍待集成与现场验收。

## 3. 验证证据应如何解读

- 测试边界纠正：早期全目录运行包含 `test_icp_fusion_bridge.py`、`test_supervisor.py` 两组历史 ROS 节点测试。它们会 `rclpy.init()`，部分输出是 mock，但诊断/种子/状态等发布器并非全部替换；当时继承 Zenoh/domain 24，不能证明测试消息与其他节点完全隔离。该测试进程已结束且未发现残留，没有 SDK 调用。先前的 1790 项结果不作为全套无图验收。统一 runner 现强制拒绝 ROS 初始化，并显式排除这两组；将来只能在单独审核的本机回环路由/隔离域中运行它们。
- Python 回归覆盖任务/取消顺序、语义路线、源时间、楼层初值、同源状态发布和 UI 生命周期；最终结果看 `python_regression.xml`。
- 最终禁止 ROS 初始化的两组 Python 回归分别为 **1746 项**（规划/定位）和 **405 项**（导航/SDK 纯逻辑）通过；BT **72 项**、Tracker **53 项** C++ 测试通过。原生 GridMap/SCAN 的测试与后续异步异常加固结果单列在 `native/NATIVE_V2.md`，不与包装层 XML 重复加总。
- BT 和 Tracker 为真实 C++ 核心测试；原生地图快照、搜索、碰撞为生产实现测试。
- 部分 FSM 方法通过提取生产方法配被动输入桩验证异步时序；这些测试证明控制流，不证明真实环境可通行。
- `source_route_audit` 对保存的 PCT 路线及其反向几何做原始支撑复核，不是两个独立的新全局求解。
- 逐束诊断若使用 09-26 近身录包，只能证明该段真实输入的原生地图行为，不能冒充 09-23 跨层整链验收。
- 本次实际逐束对照位于 `bag_evidence/recorded_0926_replay_02/`：141 个真实 CDR、310 条冻结请求加一次只读摘要；诊断 OFF/ON 的 311 次比较为零差异。近身唯一体素为自由 291、占据 1、未知 848（从未观测 844、自由证据过期 4），原始重叠计数分别 291/1/1064。前方 2 m 的 1152 个唯一体素在新鲜时全部自由，600 ms 后同一原始缓冲因证据过期全部阻止；没有把缓冲值改掉。唯一占据有后雷达射线来源，但不能据此认定轮腿干涉。
- 未运行 CPU 压力、SDK 网络故障、行人闭环仿真和实机运动；这些项目必须保持未验收，不能拿合成单元输入替代物理场景。

危险反例已有组件覆盖：过期/乱序输入、旧任务取消新任务、同 XY 不同楼层、重复高度补偿、迟到求解、错误曲线/锚/模式身份、地图快照变化、SDK ACK 顺序错误与停稳源时无进展。物理碰撞/制动安全仍没有结论。

## 4. 必须继续完成的软件工作

1. 把 `ContinuousReferenceTransport` 的 staging 运输、原生参考确认、候选提交和 BT 分段管理接成同一个 odom 预览图；目前它是实际消息回调测试组件，不是已上线 ROS 节点。
2. 完成原生地图独占写入与独立验证执行器：快照复制、owner 最终验证不能长时间堵住取消/感知回调。测量最坏耗时，而不只记录名义频率。
3. 从独立原始双雷达链完成执行安全输入及覆盖合同，取代仍依赖 LIO 筛选的 safety scan；不能只换 topic。
4. 将 SDK 模式/停止事务接到唯一写入者，统一取消→软件退役→停止提交→实测停稳；保持任务许可与物理能力验收分离。
5. 用冻结 bag 跑隔离 Zenoh 的真实组件回放，再用由控制输出驱动的仿真跑上/下楼闭环。不得把 bag 原有运动视为导航控制成功。
6. 最后做一小时持续运行、P50/P95/P99、CPU/RSS/热状态，再分阶段现场验收和 NUC 部署。

这些工作完成前不要修改 `*_verified` 标志，不要移除 `requireIntegratedControlContract` 或原始安全输入阻断，也不要开放逐束预览运动。

## 5. 物理待测项

前后雷达真实测量原点和外参；机身参考点及地面高度；轮腿/载荷在站立、行走、楼梯姿态下的包络；平地/登梯 Move 能力和比例；上/下楼保持与停止；MC 静态噪声；0.3 m/s 制动距离；发送中断、网络中断和 APP 抢占后的实际停止行为。

SDK 文档的一秒命令维持与软件 250 ms 租约不同，软件超时不等于硬件已经停车。没有这些测量，不签发跨层运动验收。
