## 修改后的交接合同

1. **参考管理观察 Native，不重演 Native CAS。** 已成功提交的原始事件必须匹配已接收
   的提案、任务、路线、坐标身份及原始全曲线证明。递增提交序号可以追上已提交状态，
   不再依赖收到所有中间通知。乱序事实使用 16 条有界账本；取消／身份重置清除旧事实。
2. **几何归属与当前可执行性分开。** 历史提交记录可恢复观察水位，但不能延长碰撞证明、
   覆盖新的占据结论或产生运动许可。新参考继续使用真实当前前置曲线 CAS。
3. **窗口尾不完成任务。** Native 到达判定使用已提交任务的真实 XYZ 目标和实测停稳；
   有限曲线耗尽仍保留本任务，等待同一路线的后继窗口。
4. **换目标保留最新意图。** 新目标取消旧工作；旧软件退役和停稳未完成时，新树不开始
   工作，不花费新任务准备预算。迟到的真实停稳事实释放同一个最新目标。worker 退役
   故障仍报告失败；旧目标的取消或结果不能取消最新目标。
5. **日志保留交接事实。** `ReferenceFlow` 输出窗口起止、实测水位、提交恢复和拒绝原因；
   Native 输出预期与实际曲线／参考编号。均限频，不按控制周期刷日志。

仍取传感器、状态及其他证据期限的最小值；不延长源数据期限、不增加过期宽容。

### 根因：任务内序号被误当成会话全局序号

每个 BT 任务新建一个 `TaskExecutionAuthority`，其 `TaskExecutionLease.sequence`
从 1 开始。SDK 新 grant 和跟踪器新任务均按此合同重置接收水位；Native 却保留上一
任务的 `task_lease_sequence_`。新任务合法低序号因而一直被丢弃，直到偶然超过旧任务
水位才可能恢复。轨迹提交与速度授权是不同消息，所以仍能显示“轨迹有效”。

Native 两个合法任务入口（参考先到、owner permit 先到）现在通过同一函数初始化
新任务的 lease、历史及序号。同任务的新参考、暂停、HOLD、断流恢复不调用该重置，
发布者级 command/permit/commit 水位保持原样；旧任务身份仍被拒绝。没有新增运动
门控、改变速度幅度、开放未知体素或删除占据。

现有 `native_motion_status` 只发布 ROS 诊断，原日志无法追溯其拒绝阶段；本轮在同一
既有诊断位置追加限频 `LocalCommandFlow`，记录任务、lease 水位、命令水位和既有
转交结果，不执行新查询。

## 全局路线离边与走廊居中

本节仅修改 PCT 全局路线质量，不修改定位、SCAN、跟踪、SDK 或地图。基线为默认包

### 原因与修改

原可见性／C2 后处理以缩短、拉直为主：只要直线不碰不可通行格，就可能把原生
PCT 留出的侧向距离再次削掉。原质量比较还要求新路线不增加长度，因此很难接受
“稍长一点、走廊中间更宽裕”的路线。仅提高原生代价权重不能解决后处理覆盖偏好的问题。

保留同次原生搜索与 GPMP，在楼层内统一比较原生、可见性和居中候选：

1. 对当前 slice 的实际可通行掩码构建距离场；地图外、缺支撑及已有禁行格仍不可用。
2. 沿有效路线查询连通横截面，寻找两侧边界之间的中心趋势；单侧边界只做有限离边，
   不追向远处空旷区。对侧向偏移使用 2 m 沿程平滑、切线 1 m 平滑和最多 4 m 两端渐变，
   不追逐门洞、墙面凹凸等短波变化。
3. 候选使用 XY C2 三次曲线；以长度、离边暴露积分及转角共同评分。额外弯曲或绕行
   过大仅否决该质量候选，仍保留原有效路线，不新增导航失败或运动许可条件。
4. 精确起终点保持原值；每条新曲线仍经过生产多项式穿格、完整支撑／净空检查，以及
   后续原定位地图回投和实测源支撑验证。未压平高度、修改膨胀或开放未知空间。

本轮还修复可见性直线端点的浮点问题：`a+(b-a)` 可能比目标差一个 ULP，原实现据此
结束整个全局任务。现显式恢复已选定的精确两端，再执行同样的完整几何验证；没有扩大
端点容差。原真实请求红绿对照差值为 `1.77635684e-15 m`。

楼梯资源保持关闭此平面优化；多 slice 路线不做平面居中。距离场按地图对象及实际掩码
指纹缓存，每对象至多两个 slice，无路线缓存；当前上下楼层已使用距离场共约 3.24 MiB。

### 根因及生产修复

原正式链每次求解后同时覆盖 Native 的待检查候选和 Follower 的待准备候选。
候选间隔最短 100 ms，而原 Native admission 整轮预算为 120 ms。因此存在合法
顺序：检查复制 curve2 → curve3 到达覆盖 → curve2 检查完成被身份 CAS 丢弃。
持续重复时，曲线一直算出来、检查也完成，却一直无法取得可提交的同一份结果。
这会延长追踪旧曲线的时间；不是已经证明所有实机摆动都由此引起。

同一真实 GridMap／ExecutionValidator／LocalFollower 输入，旧版六轮连续重叠
产生 **0 份有效候选证明、0 次新提交**；停止新增后同几何立即能提交。该用例是
可控事件顺序，不声称实机每次检查都耗时 110 ms。

现在由 Native 唯一选择正式候选并沿原 `TaggedBspline` 话题发布：

1. 一个 selected 槽完成当前验证与 prepare；新求解只合并到一个 latest 槽。
2. prepare 成功后，原候选移交既有 prepared 事务，再发布 latest。Follower 的
   exchange 独立保存该事务；后继先于 ACK 到达也不替换正在换入的曲线。
3. 负结论或不完整检查让位；无人接收的候选最多保留到**第一份原证明期限**。
   后续复核不能续长这个排队占用期限。没有添加第二套恢复倒计时。
4. 新任务、已接受参考版本替换、取消及撤销清除两槽和待发布数据；迟到候选、
   positive、ACK 仍需匹配原任务、版本、事务及证据，不会复活旧运动。
5. 当前曲线的独立碰撞复核不占候选选择权；新占据仍可立即否定当前曲线。
   自体、未知空间和原始源龄语义不变，跟踪／SDK 不增加第二套地图裁决。

这是有界工作交接，不是降低规划频率、扩大接入容差或保留过期轨迹。求解仍从
最新采集的 P/V 出发，候选失败仍保留可用当前曲线，控制器／SDK 幅度及速度
整形器历史不变。

### 一份身份合同贯穿计算、参考和退役

旧参考入口在累积 128 个退役记录后，先抛容量异常，无法清除当前 owner；
BT 适配器在接纳第 4097 次计算后又会进入永久 quarantine。回执缓存还只保留
最早一批结果，后续取消重试不能稳定获得原回执。它们会使长会话的换目标和
取消失去活性；**这不是对最近一次实机摇摆原因的推断**。

修复复用唯一 BT 已有的 `session.uint64_counter`，不增加消息版本：

| 层 | 统一后的职责 |
|---|---|
| BT 计算入口 | 接纳前检查身份；正式单调编号用常量空间水位防重复，不再按任务累计次数永久封锁 |
| 参考入口 | 同一水位封住已退役任务，换 route/hash 或更高投递序号也不能复活 |
| 当前 owner | 未接纳的未来任务取消不撤销当前 owner，当前任务仍可精确重试与取消 |
| Native 退役 | 保留原异步取消、代际与精确 ACK 合同，旧 ACK 不清除新任务 |
| 投递回执 | 有界 LRU，最多 129 个身份，保留当前及待退役 owner；回执不承担防复活职责 |

完整 session 前缀可能含点；序号仅接受规范 ASCII 正整数和 uint64 范围。
零、前导零、符号、Unicode 数字及溢出不得退化成兼容任务名绕过水位。
旧任意字符串任务仍保留有限墓碑；容量在入场前检查，并为已接纳 owner 预留
退役槽，不能因为兼容缓存用满而锁死当前任务。该容量不限制正式 BT 主线。

定位短时恢复不重建此身份历史；只有新的正式 session 才建立新历史域。
缓存重发保留原 source stamp 和投递身份，不续传感器、轨迹或运动期限。

### 修复一：连续指令与异步 SCAN 证据正确交接

20 Hz 控制输出和 SCAN 当前曲线检查不是同一个时钟。旧逻辑把一条指令截止时间固定为
它刚被转发时的证明期限；即使随后已有更新的真实正证据，**已发送指令**也得等下一次
控制采样才能受益。可复现输入中，旧指令在 41 ms 到期，下一次控制采样在 50 ms，
因此 SDK 在有效控制输出之间插入一次停车。

现在 Native 可对仍有效的同一条原始指令发送 evidence-only update；SDK 只更新它的
`valid_until`。任务、曲线、序号、速度、原始控制／body 时间及授权 lease 必须逐字段相同。
饱和前原始 payload 单独保留，防止限幅后的数值相同掩盖实际指令变更。

- 更新继续受原 body／command 100 ms、实际新 SCAN 证明及原因果任务 lease 的最早期限约束。
- 原指令已经到期、已收到零速／HOLD、取消、失权或负证明后，不允许复活。
- SDK evidence-only 到达不触发额外 `Move`，不重置 20 Hz 发送相位；控制器的速度、加速度
  和 jerk 状态也不重置。它是同一速度指令的新环境依据，不是伪造新控制采样。
- body/progress 乱序时，只保存一个带任务、曲线、原证明和停止屏障的有期限等待。
  对应原始 body 到达后补查一次；无数据不忙等、无新时间戳、不叠无界队列。

同输入生产 Native＋实际 follower＋SDK core 回归：真实新证据在 25 ms 到达，旧指令
由 41 ms 截止更新到原状态允许的 100 ms；45 ms SDK 采样不再插入零速，101 ms 仍到期。
同时覆盖过期、停止、取消、负证明以及同序号任意其他字段被修改的拒绝情况。

### 修复一：原始定位状态直接到 Native，不经过参考管理器转发

跟踪器本来直接消费 `LocalNavigationState`，Native 的独立 body 却取自 Python

日志存在 1,869 条非 hold 需求等待 `body_at_or_after_demand`，常见滞后 20～80 ms；
需求自身的原始 body 时间仍然新鲜。这里不能通过改最新时间戳或延长命令有效期解决。

正式 `task_follower_v1` 的 Native 改为直接接收同一原始 `LocalNavigationState`：

- 对齐跟踪器已有的 session、map、epoch、seed、坐标系及 provider 截止合同。
- 原始 source、IMU、posterior 和 `valid_until` 保留；速度按同次姿态转换一次。
- 原参考 body 仍可服务规划，但不再覆盖正式控制侧的原始状态账本。

实际参数生成器同时写入 `fsm.navigation_map_version_id`。必须正常准备新会话，
不能只更换二进制后复用缺少该参数的历史 `scan.yaml`。
生产 Native／跟踪核心对照覆盖参考转发额外延迟 20、50、80 ms：
旧入口重复等待，新入口无需该转发即连续接收原始需求；原期限没有延长。

### 修复二：准备异步，最终换轨与首条新需求处于同一个控制周期

最新日志有 20 条 `active_geometry_mismatch`。其中至少 12 条可与 SDK 随后的
上一条命令到期归零对应，例如 seq1383 被拒后约 44 ms，seq1382 到期停止。
原流程允许 ACK／10 ms 几何回调在两个 20 Hz 控制周期之间提前激活新轨迹，
而首条新轨迹速度必须等下一次控制 tick；在途的旧曲线速度因此失配。

新流程保持准备和 ACK 异步处理，只把最后激活绑定到控制 tick，随即生成该曲线需求。
不重置速度／加速度调节器历史；负碰撞结论和取消仍及时处理。
真实 LocalFollower＋Native＋SDK transport core 的同输入红绿对照中：
旧调度出现旧曲线被拒并归零，新调度连续承接，换轨增量仍满足原加速度约束。
红绿结果保存在 `experiments/continuity_20261020.E18_body/tracker_handoff_{before,after}.xml`。

这关闭的是已经复现的提前退休空窗。跨话题任意晚到的旧命令仍可能存在，必须拒绝；
不能宣称网络迟到已消失，也不能把旧曲线命令冒名成新曲线。

### 修复三：稳定快照角色，减少地图写入的重复工作

E17 补齐 owner 副本时会将副本提升为新 head，并再次唤醒快速检查。
若快速读者正在借原 head，提升后 owner 反而只能借正在被占用的旧 head，
造成同源追补后的短暂不可借用。对应生产池反例在修改前失败，修改后通过。

现在真实融合发布的 head 保持角色不变，同源副本只供 owner 追补，不重新触发快速
几何检查；保留三槽固定上限和借出槽不可覆盖约束。不恢复 E17 前副本长期过旧的问题。

此外，生产射线遍历保留每条射线和全部穿格步骤，仅优化同轮重复访问：

首次新源访问仍更新原始时间最大值，全轮每格仍只投一次 free 票。

### 修复一：同一条指令更新证据时保持原授权身份

现有链路允许新的 SCAN 正证明及时更新已发送指令的证据截止，
不必等待下一个 50 ms 控制周期。漏洞在于：一条生成较早、到达较晚的同任务心跳
会改变重新组装指令时选择的 `lease_sequence`。严格同载荷比较只允许修改证据截止，
因此整次刷新被丢弃；原指令可能在下一条速度到达前短暂过期。

修复将“原指令的证据刷新”与“新运动需求的授权选择”分开：

- 新需求照常选择当时可用的原始授权。
- 同一指令刷新固定其已经发送的授权编号，仅更新真实证据允许的截止。
- 原授权、当前授权、原指令和原机身状态都必须仍有效；不能借新心跳复活旧指令。
- 不增加碰撞检查，不改 SDK，不重写源时间，不延长原 100 ms 指令／机身期限。

生产 Native＋SDK transport core 同输入对照：
原实现因晚到心跳拒绝刷新，修复后在 `101.045 s` 不再插入零速；
到原始状态期限 `101.101 s` 仍停止。
原授权已过期而新授权仍活跃、负碰撞结论、HOLD、取消和撤权均不能复活原输出。
红绿日志为 `e19-lease-red.log`、`e19-lease-green.log`、`e19-lease-all.log`；
15 项生产核心时序测试通过。该测试证明竞态被关闭，不代表所有现场到期都由它造成。

### 修复二：就绪射线立即调度，保留丢帧原因
