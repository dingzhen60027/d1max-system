# D1 Max 导航开发主线

## 唯一主线

用户已于 2026-10-03 确认：以当前 BehaviorTree.CPP 导航框架作为唯一开发主线。
用户于 2026-10-04 明确：架构面向室内外、多楼层导航，单楼层只是当前测试范围。
正式公开会话名称为 `d1max_pct_scan.navigation_session`，统一公开入口为
`tools/navigation_entry.sh`。旧 `single_floor_session` / `single_floor_entry.sh`
只作为同一实现与已封存版本的兼容名称，不代表另一个导航框架。
单层、跨层、室内外能力在这一套框架中逐步实现，
不得另搭导航上层、第二个任务管理者或竞争 SDK 的控制链。

职责保持解耦：BT 管任务；全局规划计算固定路线；参考管理按实测进度截取窗口；
局部规划产生候选；验证与提交管理换轨；跟踪器输出运动需求；安全门和唯一 SDK
writer 管最终发送及停止证据。算法通过配置和接口替换，不把 PCT/SCAN 写死到上层。

## 工作方式

- 在现有工作区和当前 Git 分支上推进。没有用户明确要求，不另建或切换 Git 分支，
  不 fork 一套平行导航工程。保留已有未提交改动。
- 隔离构建、模拟 SDK、离线回归和 `experiments/` 是同一主线的验证产物，
  不是另一条开发路线，也不能成为第二个正式入口。
- 旧预览、旧 motion coordinator、旧 Nav2 入口仅作历史兼容，不接管主线任务或运动。
- 通信保持 Zenoh；不擅自切换 DDS 中间件。
- 导航显示只允许一个 RViz 进程；全局/局部在同一窗口切换，不同时打开两套布局，
  不因显示切换重启任务、定位或规划。Web 只提供一个 RViz 打开入口。
- 当前阶段优先收敛框架、模块合同和局部连续性；按用户最新要求，暂不新增完整 rosbag 回放验证。

## 版本与验收

“主线”不等于“已部署/已验收”。源码、安装产物、整图结果和物理验收分开记录。
默认 release 由既有 `deploy/single_floor_release.json` 明确选择；文件名保留版本兼容，
不定义架构范围、不按目录时间自动切换。当前单层能力合同和未验收项不能因公开改名而放开；
候选包和回退快照不是新的架构分支。部署、生产服务重启、SDK 接管及现场运动必须按
用户相应授权执行，不因本主线约定自动授权。

不得通过修改未验收标志、放开全部未知空间、近身清空或重写源时间宣称导航通过。
当前工程状态以 README 指向的状态文档为准；历史测试结果必须保留原版本和适用范围。
